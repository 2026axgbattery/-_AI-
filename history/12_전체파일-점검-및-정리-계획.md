# 12. 전체 파일 점검 및 정리 계획

## 배경/동기

저장소에 기획 문서가 `.docs/01`~`11`까지 누적되면서, 완료된 1회성 계획 문서와 계속 참조해야 하는 활성 문서가 섞여 있는지, 문서 간 내용이 서로 어긋나는 곳은 없는지 전체적으로 다시 점검해달라는 요청을 받았다. 목적은 (1) 문서 간 모순·깨진 참조가 없는지 더블체크하고 (2) 더 이상 쓰지 않는 파일은 `history/`로 옮기고 (3) 실제로 계속 참조할 파일만 저장소 루트/`.docs/`에 남기는 것이다.

## 범위

- `history/`를 제외한 저장소 내 모든 파일: 루트의 `CLAUDE.md`/`prd.md`/`design.md`/`domain-constants.md`/`correlation-reliability-review.md`/docx, `.docs/01~12` 및 `.docs/phase/*`, `output/*.html`, CSV 2개.
- `history/` 내부 파일은 이미 "참조 금지"로 분류돼 있으므로 재분류 대상에서 제외(단, 새로 옮길 파일이 있으면 `history/README.md`에 등록).

## 방법

1. 각 활성 문서를 읽고 다음을 확인한다:
   - CLAUDE.md의 "저장소 내 파일 구성" 절에 설명된 역할과 실제 내용이 일치하는가.
   - 문서 간 상호 참조(파일명, 경로)가 깨지지 않았는가.
   - 최근 결정 사항(2026-09-10 스택 피벗, 화면 통합, 디자인 개편 등)이 모든 관련 문서에 일관되게 반영됐는가.
2. 각 파일을 "계속 활성 참조 문서"와 "완료된 1회성 산출물(더 이상 참조 불필요)"로 분류한다. 단, `.docs/01`처럼 완료됐지만 "새 계획 작성 시 형식 참고용"으로 CLAUDE.md에 명시적으로 남겨둔 전례가 있으므로, 완료 여부만으로 기계적으로 옮기지 않고 향후 참조 가치를 함께 판단한다.
3. 이동 대상은 `history/`로 옮기고 `history/README.md`에 이동 사유와 대체 문서를 기록한다.
4. 파일 구성이 바뀌면 `CLAUDE.md`의 "저장소 내 파일 구성" 절도 최신 상태로 갱신한다.

## 완료 기준

- 모든 활성 파일에 대해 점검 결과(문제 없음/수정함/이동함)를 사용자에게 보고한다.
- 발견된 불일치·깨진 참조는 고치거나, 고치지 않기로 한 경우 이유를 명시한다.
- `history/`로 옮긴 파일은 `history/README.md`에 반영되고, 저장소 루트/`.docs/`에는 실제로 쓰는 파일만 남는다.
- `CLAUDE.md`가 최종 파일 구성과 일치하도록 갱신된다.
