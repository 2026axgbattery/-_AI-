# 28. 상세분석·예측 화면에 "전체/형명별/바이어별" 구분 조회 — 작업 계획서

## 배경/동기

- 사용자 요청: `/detail-analysis`의 형명 요약 배너+게이지 위에 "전체/형명별/바이어별" 3가지 구분으로 평균 결과값을 볼 수 있는 선택 UI를 추가하고, `/prediction`에도 동일한 3구분으로 예측 결과를 분석할 수 있게 해달라.
- 조사 결과(서브에이전트 확인): "바이어(buyer)"는 별도 저장 컬럼이 아니라 `model_name` 접미 문자(예: `AGM70_H2` → `H`)에서 `extract_buyer_code_from_model_name`(`backend/analysis/derive.py`)로 그때그때 뽑아내는 파생값이다. `Lot`/`ProcessData`에 buyer 컬럼 자체가 없다(`docs/prd.md` §10-19: model_name 접미문자=바이어 코드로 확정 채택). `ChargeProgramSpec.buyer_code`만 실제 저장 컬럼이며 충전 STEP 기준표 매칭 전용이다.
- 회귀(1·2단, CCA)는 애초에 형명 구분 없이 전체 로트를 합쳐 학습하는 구조(`get_x_to_y_training_rows` 등에 `WHERE model_name=` 필터가 없음) — 이건 이번 범위에서 바꾸지 않는다(CLAUDE.md "회귀 로직 자체는 수정하지 않음" 원칙 유지, 형명별/바이어별 별도 회귀 학습은 훨씬 큰 아키텍처 변경이라 v2 논의 대상). 이번 작업은 **이미 계산된 실측/예측 결과를 3가지 단위로 집계·필터링해 보여주는 조회 기능**으로 범위를 한정한다.

## 범위

1. `/detail-analysis` 형명 요약(배너+게이지 4개)에 전체/형명별/바이어별 선택 탭 추가 — 백엔드 변경 없이 이미 받아온 `GET /api/models/summary` 응답(형명별 평균 Y·Z·CCA 집계)을 프런트에서 재집계(가중평균)한다. 기존 "35개 형명 전체 표"·"Y 추이" 섹션은 그대로 둔다(범위 밖).
2. `/prediction`의 "미매칭 로트 일괄 예측" 탭 결과 표에 동일한 3구분 탭 추가 — 이미 받아온 `POST /api/predict/batch-unmatched` 응답의 `results`(로트별 `model_name` 포함)를 프런트에서 필터링 + 구분별 합격/불합격 집계 요약을 보여준다. 회귀 자체(POST 호출)는 항상 전체 로트 대상으로 1번만 실행(기존과 동일).
3. "조건 시뮬레이션(수동 입력)" 탭은 변경하지 않는다 — 단일 가정 조건은 정격용량이 필요해 물리적으로 형명 1개 단위로만 의미가 있고(바이어/전체 평균으로는 어떤 정격용량을 쓸지 정의 불가), 이미 모델명 입력란이 있어 "형명별"에 해당한다.

## 방법

- 신규 공용 유틸 `frontend/lib/buyer.ts` — `extractBuyerCode(modelName)`을 백엔드 정규식(`^[A-Za-z]+\d+_([A-Za-z]+)`)과 동일하게 구현.
- `/detail-analysis`: `scope`("all"|"model"|"buyer") 상태 + 형명/바이어 선택값 상태 신규. `summary.models`(이미 fetch됨)를 선택 범위로 필터링해 로트 수 가중평균(avg_retention_rate·avg_capacity_rate)과 CCA pass/evaluated 합산으로 재집계하는 `aggregateModels` 헬퍼 추가. 기존 `spotlightModel` 기반 배너·게이지 4개를 이 집계 결과로 교체. 35개 표에서 형명명을 클릭하면 scope를 자동으로 "형명별"+해당 형명으로 전환(기존 클릭 동작 유지). 탭 UI는 기존 `.period-tab`/`.model-select-row` 클래스 재사용(신규 CSS 없음).
- `/prediction` 배치 탭: `predScope` 상태 + `batchResult.results`를 클라이언트에서 필터링하는 `scopedRows` + Y/Z/SAE/EN 각각의 합격·불합격 건수를 세는 `summarizeBatch` 헬퍼 추가. 탭 UI 동일하게 재사용.
- 새 백엔드 엔드포인트·회귀 로직 변경 없음.

## 완료 기준

- `/detail-analysis`에서 전체/형명별/바이어별 탭을 눌러 배너·게이지 4개(Y·Z·EN·SAE CCA)가 선택 범위에 맞게 재계산돼 바뀜을 확인.
- `/prediction` 배치 탭에서 같은 3탭으로 결과 표·요약이 필터링됨을 확인.
- `npm run build`·`npm run lint` 통과, 백엔드 변경 없으므로 `pytest`/`ruff` 재실행 불필요(변경 파일 없음 확인 후 생략 명시).
