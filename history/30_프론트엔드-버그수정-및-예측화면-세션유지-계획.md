# 30. 프론트엔드 버그 수정 + 예측 화면 세션 유지 — 작업 계획서

## 배경/동기

사용자가 두 가지를 요청함:
1. "전체적으로 HTML 구현 시 버그는 없는지 점검" — `code-review` 스킬로 `frontend/app`·`frontend/components`·`frontend/lib` 전체를 고효과(high effort)로 점검(이 저장소는 git 저장소가 아니라 diff 기반이 아니라 스냅샷 전체 리뷰로 진행), 10건 확인.
2. "/prediction에서 분석(예측) 결과가 나온 뒤 다른 페이지로 넘어가면 데이터가 다 사라진다 — 새로고침 또는 '다시 분석'을 누르면 복원되게 할 수 있는지 검토".

원인 확인: Next.js App Router는 `<Link>`로 다른 라우트에 이동하면 이전 라우트의 컴포넌트 트리를 언마운트한다. `/prediction`의 `manualResult`/`batchResult`(+선택된 스코프·지표)는 순수 `useState`라 언마운트 시 사라지고, `/dashboard`와 달리 이 값들은 서버에 "최신 예측 결과"로 조회할 수 있는 GET 엔드포인트가 없다(예측은 매번 파라미터화된 요청이라 "그 최신값" 개념 자체가 없음 — 수동 시뮬레이션은 입력값에 의존, 일괄 예측은 매번 전체 로트를 다시 계산하는 구조). `/dashboard`는 반대로 `AnalysisRun`에 영속화되고 `GET /api/analysis/latest`로 다시 불러오므로 이 문제가 없음(비교 대상으로 확인만 하고 변경하지 않음).

## 범위

### A. `/prediction` 결과 세션 유지(이번 작업의 핵심 요청)

- 수동 시뮬레이션 탭: 입력값(`modelName`, `xValues`)과 마지막 예측 결과(`manualResult`)를 `sessionStorage`에 저장, 마운트 시 복원.
- 미매칭 일괄 예측 탭: 마지막 예측 결과(`batchResult`)와 선택된 뷰 상태(`batchScope`/`batchScopeDate`/`batchScopeModel`/`batchScopeBuyer`/`batchMetric`)를 `sessionStorage`에 저장, 마운트 시 복원.
- 탭(수동/일괄) 선택 자체도 함께 저장해 어느 탭을 보고 있었는지 유지.
- 새로고침(F5)·다른 페이지 갔다가 복귀 둘 다 복원되어야 함(둘 다 컴포넌트 언마운트를 유발하므로 `sessionStorage`가 둘 다 커버). 탭을 완전히 닫으면(sessionStorage 특성상) 사라지는 것은 의도된 동작(오래된 예측 결과를 영구 보존할 이유는 없음 — 데이터가 바뀌면 결과가 stale해질 수 있어 "다시 분석/예측 실행" 버튼으로 언제든 재계산 가능하게 유지).
- 저장 크기가 크지 않은지 확인(배치 결과는 최대 수천 건 — 필요 시 `BATCH_TABLE_LIMIT`처럼 저장 범위를 제한할지 검토, 실제 크기 먼저 측정 후 결정).

## 방법

- `/prediction`: `sessionStorage` 읽기/쓰기를 감싼 소규모 헬퍼(`try/catch`로 감싸 프라이빗 브라우징 등에서 예외 발생해도 앱이 죽지 않게) + `useEffect`로 마운트 시 1회 복원, 값이 바뀔 때마다(`useEffect` 의존성) 저장. 새 백엔드 API 없음(A 항목).
- 버그 수정(B 항목)은 각 파일의 기존 패턴(`.catch(() => null)`, `disabled={xLoading}` 등)을 그대로 따라 최소 수정.
- CCA 원인 인자 중복 제거는 `backend/routers/prediction.py`의 `_predict_en_cca_block`에서 병합 후 `factor` 기준으로 dedupe(더 큰 절대 기여도만 남김)한 뒤 `rank`를 다시 매김.

## 완료 기준

- `npm run build`·`npm run lint`(프런트) 통과.
- `pytest tests/backend`·`ruff check backend`(백엔드 변경분 있음 — #2) 통과.
- `/prediction`에서 예측 실행 → 다른 페이지로 이동 → 복귀 시 결과·선택 상태가 그대로 보이는지 실제 확인(가능하면 브라우저 확인, 불가 시 로직 검증으로 대체 명시).
- 이 문서 자체는 완료 후 `history/`로 이동하고 `.docs/07`(디자인 변경 시)·`CLAUDE.md`(전체 요약)에 결과 반영.
