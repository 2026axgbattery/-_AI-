# v1.1 확장 계획 — 충전 STEP SPEC 이탈도 · CCA 이중 예측 · Y-Z 상관분석 확장

## 배경

팀장 보고(2026-09-18, `reports/2026-09-18_팀장보고_전지포화도용량예측시스템.pptx`) 후 받은 피드백:

1. X 인자 중 충전 방법(STEP)을 형명·브랜드별 SPEC/STEP 기준(엑셀 양식)으로 미리 등록해두고, 그 기준표를 근거로 분석 대상 형명·브랜드의 X 인자(셀중량부터 전체 공정 데이터)가 충방전에 따른 화학반응을 얼마나 따르는지 확인할 수 있게 할 것.
2. Z 인자에 20시간 용량뿐 아니라 CCA 결과도 추가로 받아 예측 대상에 포함하고, X-Y-Z 상관관계 분석도 가능하게 할 것 — 특히 포화도(Y)가 높아짐에 따른 CCA와의 관계를 확인.

이 문서는 위 피드백을 PRD → 스키마 → 백엔드 → 프런트 순서로 반영하기 위한 상위 계획이다. 범위가 커서 단계(Phase)를 나누고, 각 Phase는 착수 가능 시점이 다르다.

## 방향 확정 (사용자 질의응답, 2026-09-18~21)

- **STEP 기준표**: 실제 사내 양식을 사용할 예정이며 추후 전달받는다(SPEC 값 포함). 반영 방식은 "실적값의 STEP 기준 대비 이탈도"를 **새 파생 X 인자**로 만들어 1단(X→Y)·2단(X+Y→Z) 회귀에 투입한다(정보 표시용 배지에 그치지 않음).
- **CCA 구조**: 20시간 용량(Z1)과 완전히 별개의 두 번째·세 번째 예측 타겟(Z2=SAE CCA, Z3=EN CCA)으로 추가한다. 각각 독립적으로 2단 회귀·SPEC 판정·원인진단을 수행하고, Y↑에 따른 Z1·Z2·Z3 각각의 관계를 모두 확인할 수 있게 한다.
- **CCA 데이터 출처**: `AGM 시험현황_raw data.xlsx`의 `SAE CCA(1차)\n18℃ 24H 방치` 구간과 `EN CCA 18℃` 구간의 `방전량`(Ah) 행. 값 자체는 사용자 확인 완료("그 값이 SAE/EN CCA 결과값").
  - 이 워크북은 단일 신뢰성 배치(로트 접두 `070C26D010217`, `AGM70_H2`, 20개 샘플) 1건뿐이라 SAE·EN 각각 2개 샘플만 값이 있음 — 표본이 극히 작지만 "우선 파이프라인만 구축"하기로 확정(사용자 확인). 향후 다른 신뢰성 배치 파일이 추가되면 같은 파서로 계속 누적된다.
  - 기존 `TestData.initial_cca`(공정 SPC DATA의 `MT(A)`를 CCA 대용으로 써온 간이 추정치, Amp 단위로 추정, 예 442.3)는 **그대로 유지**한다. 사용자 확인: "init_cca는 간이적으로 측정한 값이며 이번 SAE/EN CCA와 같은 단위가 아님 — 참고치". 즉 `initial_cca`/`sae_cca`/`en_cca`는 서로 다른 세 값으로 공존한다.
  - `EN CCA 18℃` 섹션명은 워크북 내에 **두 번 등장**한다(신뢰성 시험 프로토콜상 다른 체크포인트에서 재측정하기 때문). 첫 번째 occurrence는 이번 파일에서 전부 공란이고, 두 번째 occurrence에만 실측값(7.626, 6.903)이 있다. 파서는 섹션명 중복을 전제하고 **실제 값이 채워진 occurrence를 선택**하도록 만들어야 한다(구간명 최초 등장만 보는 기존 `_build_row_map`을 그대로 쓰면 빈 블록을 골라 조용히 전부 NULL이 되는 버그가 생김).

## Phase A — CCA 데이터 파이프라인 구축 (지금 바로 착수)

SPEC 값 없이도 가능한 부분. 범위:

1. **스키마**: `TestData`에 `sae_cca REAL`, `en_cca REAL` 컬럼 추가(NULL 허용, append-only 원칙 유지).
2. **ETL 파서** (`backend/etl/test_raw.py`): 섹션명 중복에 안전하도록 행 매핑 구조를 "첫 occurrence"에서 "occurrence 목록"으로 바꾸고, 새 `sae_cca`/`en_cca` 필드는 "실측값이 있는 occurrence 우선" 규칙으로 행을 고른다. 기존 필드(제조로트·전압·저항 등)는 첫 occurrence 규칙을 그대로 유지해 회귀 위험을 최소화한다.
3. **저장소** (`backend/db/repository.py`): `TEST_DATA_COLUMNS`에 `sae_cca`/`en_cca` 추가. 단 CSV 업로드 경로(`test_data.csv`)는 이 두 컬럼 헤더가 없어도 그대로 동작해야 하므로(기존 더미 CSV·실 CSV 템플릿 깨짐 방지), `REQUIRED_TEST_COLUMNS`에서는 제외하는 "선택 컬럼" 개념을 도입한다(`fill_weight`/`water_loss` NULL 허용과 같은 기존 철학).
4. **테스트**: `tests/backend/test_test_raw.py`에 EN CCA 섹션명이 중복되는 상황(하나는 공란, 하나는 실측값)을 재현하는 픽스처를 추가해 올바른 occurrence를 고르는지 검증.
5. **PRD 갱신**: `prd.md` §7 데이터 모델(TestData)에 `sae_cca`/`en_cca` 필드 설명 추가.
6. 회귀·SPEC 판정·원인진단(Z2/Z3로 실제 예측에 쓰는 것)은 표본이 2건뿐이라 지금 단계에서는 의미가 없다 — **Phase C로 미룬다**. Phase A는 "값을 정확히 저장하고 조회할 수 있게" 하는 데까지만.

## Phase B — 충전 STEP SPEC 기준표 반영 (완료, 2026-09-21)

### 확정된 방향 (질의응답)
- 원본 파일: `★ 260428 AGM CF 충전 프로그램 3.xlsx`(사내 실제 양식). 정격용량군별 시트(50/60/70/80/92/105) 안에 바이어 코드 그룹별 충전 STEP 프로그램이 나란히 배치된 구조.
- model_name 접미 문자(H/Y/S/...)만 바이어 코드로 본다(뒤 숫자는 무시).
- 같은 (정격용량, 바이어 코드)에 기본/임시(변경) 버전이 함께 있으면 기본을 우선 사용.
- "1세대"(1G- 접두 구형 모델) 시트는 제외 — 어느 세대인지 판단할 근거(극판 세대)가 현재 데이터에 없음.
- 이탈도는 "실제 총 충전량(charge_amount) vs 프로그램 Total 충전량[Ah]"만 우선 계산(STEP별 세부 비교는 공정 데이터에 세부 전류/시간이 없어 불가 — 향후 데이터 확보 시 확장).
- 원본의 "92"(AGM92) 라벨은 실제로는 정격 90Ah 제품이다(방전효율 요약 시트의 "AGM90" 행과 총 충전량이 정확히 일치해 교차검증됨, 사용자 확인) → 90으로 정규화해서 저장.

### 구현
- `backend/etl/charge_program.py`(신규): 워크북 파서. 개발 중 실 파일에서 버그 3개 발견·수정 — (1) 제목 셀 줄바꿈으로 정규식 매칭 실패, (2) STEP과 Total 행 사이 빈 행으로 스캔 조기 종료, (3) Total 라벨이 "구분" 컬럼이 아니라 선행 컬럼에 잘못 들어간 원본 오탈자.
- `backend/db/schema.sql`: `ChargeProgramSpec`(참조/마스터 테이블, 재업로드 시 전체 교체) 신규, `LotDerived.charge_program_deviation_pct` 신규.
- `backend/analysis/derive.py`: `extract_buyer_code_from_model_name`, `compute_lot_derived`에 이탈도 계산 추가.
- `backend/db/repository.py`: `get_active_charge_program_total_ah`(기본 우선, 없으면 'All' 폴백), `replace_charge_program_specs`, `recompute_all_lot_derived`(기존 로트 소급 반영). `ingest_process_rows`·수기입력 재계산 경로에도 연결.
- `backend/routers/charge_program.py`(신규): `POST /api/charge-program/upload`, `GET /api/charge-program`.
- `backend/analysis/regression.py`: `X_COLUMNS`에 `charge_program_deviation_pct` 추가(팀장 확인 방향 — 이탈도를 새 X 인자로 회귀 투입).
- `frontend/app/prediction/page.tsx`, `frontend/app/dashboard/page.tsx`: 새 인자 한글 라벨("충전 프로그램 이탈도(기준 대비 %)") 추가.

### 발견·수정한 부수 버그
- **VIF 무한대 시 API 500 크래시**: `compute_vif`가 완전 다중공선성일 때 `float("inf")`를 반환하도록 이미 설계돼 있었는데, FastAPI 기본 JSONResponse는 `Infinity`를 직렬화하지 못해 그대로 두면 500 에러가 난다. 이번에 `charge_program_deviation_pct`가 `charge_ratio`와 함께 단일 형명(AGM70_S1) 데이터에서 실제로 VIF=inf를 유발해 재현·확인됨. `backend/analysis/vif.py`에서 JSON-safe한 큰 유한값(9999.0)으로 캡핑하도록 수정.

### 중요 — 운영상 새로 생긴 전제조건
`charge_program_deviation_pct`가 1단 X셋의 필수 컬럼이 됐다(다른 X 인자와 동일하게 "모두 채워진 로트만" 회귀에 사용하는 기존 규칙을 그대로 따름). **충전 프로그램 기준표를 한 번도 업로드하지 않은 상태(빈 DB 등)에서는 공정 데이터를 아무리 올려도 1단·2단 회귀가 표본 부족으로 실행되지 않는다** — `POST /api/charge-program/upload`로 기준표를 먼저(또는 그 이후 아무 때나, 업로드 시 기존 로트까지 소급 재계산됨) 올려야 정상 동작한다. 미매칭 로트 일괄 예측(`/api/predict/batch-unmatched`)은 프로그램이 매칭되지 않는 로트만 조용히 제외하고 계속 동작(크래시 없음).

### 검증
- 실제 원본 파일 파싱: 30개 프로그램 블록(6개 용량군 × 바이어 코드) 전부 추출, `방전효율` 요약 시트와 Total 충전량[Ah] 전부 일치 확인.
- 로컬 `app.db`(AGM70_S1 1200로트)에 실제 반영: 커버리지 1200/1200, `/api/analysis/x-to-y`·`/api/analysis/xy-to-z`·`/api/predict/manual`·`/api/predict/batch-unmatched` 전부 실제 HTTP 요청으로 200 확인.
- 다만 현재 로드된 데이터가 단일 형명(AGM70_S1)뿐이라 `charge_ratio`·`charge_program_deviation_pct`가 서로 완전 비례(VIF=9999.00 cap)함 — 여러 형명·바이어 데이터가 섞이면 이 두 인자가 독립적인 신호를 갖게 된다(다른 바이어 프로그램의 Total 충전량이 정격용량에 단순 비례하지 않음, 예: AGM70 B/S=456.5 vs D=406.75 vs G=448.25).
- `pytest tests/backend -q`(57건) · `ruff check backend` · `next build`/`eslint` 통과. Playwright로 `/dashboard`·`/prediction` 콘솔 에러 없음, 새 인자 한글 라벨 정상 표시 확인.

### 현재 표본 상태 (지어내지 않음, 그대로 기록)
- SAE CCA 실측 2건, EN CCA 실측 2건(서로 겹치지 않는 로트) — `_fit_linear`의 최소 표본
  (`len(X_COLUMNS)+2`=11건) 미달이라 `POST /api/analysis/xy-to-{sae,en}-cca`는 지금도
  `InsufficientSampleError`(400, "회귀에 필요한 최소 표본 수(12건) 미달: 유효 표본 2건")를
  정상적으로 반환한다 — 이는 버그가 아니라 데이터가 실제로 그만큼뿐이라는 사실이다.
- 신뢰성 배치 데이터가 더 업로드되면(같은 `AGM 시험현황_raw data.xlsx` 계열 파일을
  `POST /api/upload/test`로 계속 업로드) 표본이 쌓여 자동으로 회귀가 성립한다 — 코드 변경 불필요.

### 발견·수정한 부수 버그 (Phase C 작업 중)
