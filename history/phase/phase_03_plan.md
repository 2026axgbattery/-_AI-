> `prd.md` §6 ④-1·④-2·⑤를 구현하고, 3일 집체 결과물을 종단간으로 검증·마무리하는 날. **2026-09-10 스택 피벗 반영**: 화면(Next.js)·API(FastAPI) 경계로 작업을 나눈다.

## 작업 순서

1. **`backend/analysis/regression.py` 확장**: `predict_y`(미매칭 41개 로트에 1단 최신 run 적용), `predict_z`(Ŷ + X를 2단 최신 run에 적용, `input_y_source='predicted'` 플래그 부여). 실측 Y가 있는 시험 매칭 로트로 수동 시뮬레이션할 경우 `input_y_source='measured'`로 구분. API: `POST /api/predict/y`, `POST /api/predict/z`.
2. **`frontend/app/prediction/page.tsx`**: `output/04_prediction.html` 이식, 두 탭 유지 — "조건 시뮬레이션(수동 입력, 선택적)"과 "미매칭 로트 일괄 예측(X 자동 입력)". 배치 결과 테이블에 Y/Z 값과 "Ŷ 기반" 배지, 이상치(음수 등 물리적으로 불가능한 값) 플래그 표시(§8).
3. **`backend/analysis/diagnosis.py`**: `judge_spec`(모델별 `ConstantsByModel.spec_lower_y`/`spec_lower_z`와 비교 — 값이 없으면 "SPEC 미설정, 판정 불가" 안내로 대체, §8 마지막 행), `rank_causes`(회귀계수 × SPEC 이탈도로 원인 인자 순위화, Y/Z 원인 인자셋 분리, 동률 처리 규칙은 §10-12 확정 전까지 "계수 절댓값 큰 순 + 동률 시 인자명 알파벳 순" 임시 규칙 적용 후 TODO 주석으로 남김). 원인진단 문구가 항상 "주액량 증대"로만 귀결되지 않도록 규칙 문구를 여러 갈래(증발/누액, 화성 부족/계량오류, 극판 공극 증가)로 분기. API: `POST /api/diagnosis`.
4. **`SpecJudgment`/`CauseDiagnosis` 저장 연동**: 예측 API 호출 시 자동으로 판정·진단 결과까지 이어서 저장.
5. **종단간(①→⑤) 점검**: `next dev` + `uvicorn`을 새로 띄운 뒤, DB를 비운 상태에서 업로드→매칭→수기입력→1·2단 분석→상세분석/추이→예측→SPEC/진단까지 클릭만으로 1회 완주. 각 단계에서 에러 발생 여부, `prd.md` §8 엣지케이스 표의 각 행이 실제로 그렇게 동작하는지 표로 체크.
6. **개발 후 점검(전역 CLAUDE.md 규칙)**:
   - 백엔드: `backend/analysis/` 대상 `pytest` 유닛 테스트(각 함수의 정상 입력/경계 입력) 실행, lint(`ruff` 또는 `flake8`) 실행.
   - 프런트: `next build`(타입 체크 겸용, TypeScript strict 모드 기준 오류 없어야 함), `eslint` 실행.
   - 실패 항목은 결과와 함께 별도로 보고하고, 생략한 점검이 있으면 명시한다.
7. **디자인 마무리**: `design.md` 색상·타이포·간격 토큰 위반 여부(오렌지·그린 동시 강조, `sebang-gray-500` 본문 사용 등) 5개 화면 전수 확인. 이번 피벗으로 "디자인 완성도는 v2 목표"가 아니라 **MVP 자체의 완료 기준**이 됐으므로, `output/*.html`과의 시각적 diff를 화면별로 스크린샷 비교한다.
