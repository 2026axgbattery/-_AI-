# 13. 업로드 이력 확인 · 선택 삭제 · 전체 삭제 기능

## 배경/동기

Day 1 구현·검증을 반복하는 과정에서, 잘못 업로드한 파일이나 테스트용 더미 데이터를 지우고 다시 시작하려면 지금은 `backend/db/app.db` 파일을 직접 지우고 서버를 재시작해야 했다. 사용자가 업로드 화면 안에서 "지금까지 업로드된 파일 목록을 확인하고, 특정 파일만 골라 지우거나, 전체를 한 번에 지울 수 있는" 관리 기능을 요청했다.

**append-only 원칙과의 관계**: `prd.md`/`.docs/03`가 정의한 append-only 원칙(재업로드해도 기존 이력을 덮어쓰지 않고 계속 쌓는다)은 실제 운영 중 데이터 흐름에 대한 원칙이다. 이번에 추가하는 삭제 기능은 그 원칙을 깨는 게 아니라, "잘못 올린 파일을 되돌리는" 별도의 명시적 관리자 조작이다. 두 개념이 문서상 충돌하지 않도록 `prd.md`에 이 구분을 명시한다.

## 범위

- **포함**:
  - 업로드 시점마다 "이 업로드로 어떤 로트가 들어왔는지"를 추적하는 `UploadBatch` 테이블 신설, `ProcessData`/`TestData`에 `upload_batch_id` 컬럼 추가.
  - `GET /api/upload/batches` — 업로드 이력 목록(파일 종류, 파일명, 건수, 업로드 시각).
  - `DELETE /api/upload/batches/{batch_id}` — 해당 업로드로 들어온 행만 선택 삭제. 그 결과 어떤 로트에 `ProcessData` 행이 하나도 남지 않으면 그 로트(`Lot`/`LotDerived`/`TestData`/`Prediction`/`SpecJudgment`/`CauseDiagnosis`)까지 함께 정리(고아 데이터 방지).
  - `DELETE /api/upload/data` — 전체 삭제(모든 테이블 초기화, DB를 빈 상태로).
  - 업로드 화면(`frontend/app/upload/page.tsx`) 맨 아래에 "업로드 이력" 카드: 목록 + 항목별 "삭제" 버튼(확인 다이얼로그) + "전체 삭제" 버튼(더 강한 확인 문구).
- **비범위**: Day 2/3 분석 결과(`AnalysisRun` 등)에 대한 개별 삭제 UI는 다루지 않는다(아직 생성되는 화면이 없음). "전체 삭제"는 이 테이블들도 함께 비운다(완전 초기화 목적).

## 방법

1. `backend/db/schema.sql`: `UploadBatch(batch_id PK, file_type, filename, row_count, uploaded_at)` 추가, `ProcessData`/`TestData`에 `upload_batch_id INTEGER REFERENCES UploadBatch(batch_id)` 컬럼 추가. 현재 개발 단계(운영 데이터 없음, `app.db`는 로컬 산출물·git 미포함)이므로 마이그레이션 스크립트 대신 스키마를 직접 수정하고 DB 파일을 새로 생성하는 방식으로 반영한다.
2. `backend/db/repository.py`: 업로드 시 배치 레코드 생성 + 각 행에 `upload_batch_id` 태깅. `delete_upload_batch`(배치 삭제 + 고아 로트 정리), `delete_all_data`(전체 초기화), `get_upload_batches` 추가.
3. `backend/routers/upload.py`: 위 3개 엔드포인트 추가.
4. `frontend/lib/api-client.ts` + `app/upload/page.tsx`: 업로드 이력 카드 추가, 업로드·삭제 후 목록·매칭 요약·수기입력 상태를 모두 새로고침.
5. Playwright로 실제 업로드 → 이력 확인 → 선택 삭제 → 전체 삭제까지 헤드리스 브라우저로 검증.

## 완료 기준

- 업로드 화면 맨 아래에서 지금까지 업로드한 파일 목록(종류·파일명·건수·시각)을 볼 수 있다.
- 특정 항목을 삭제하면 그 업로드로 들어온 데이터만 지워지고, 다른 업로드분은 그대로 남는다(고아 로트는 함께 정리됨, FK 오류 없음).
- "전체 삭제"를 누르면 DB가 완전히 빈 상태로 돌아간다(모든 테이블 0건).
- 삭제 후 매칭 건수·수기입력 완료율·업로드 이력이 화면에 즉시 반영된다.
