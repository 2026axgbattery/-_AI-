# 업로드·매칭·수기입력 화면 통합 + 드래그앤드롭 업로드 계획

## 배경/동기
- 사용자 확인: 현재 목업 구조상 CSV 업로드 → lot_id 매칭은 `output/01_upload_matching.html` 한 화면에서 **자동으로** 계산되어 보여지지만(별도 "매칭 실행" 버튼 없음), 그 뒤 **1단·2단 회귀 분석은 별도 액션(버튼)을 눌러야 실행**되는 구조였다. 즉 "업로드하면 바로 전체 분석까지 자동 실행"되는 구조는 아니었다.
- 이를 확인한 사용자가, 수기입력(그룹 일괄 입력)을 별도 화면(`02_manual_entry.html`)으로 분리할 필요 없이 업로드·매칭 화면 바로 아래에 붙여서 한 화면에서 끝내자고 결정했다. 이는 지난 세션에 `prd.md` §10-20/`.docs/07_디자인-수정-이력.md`(2)에 "결정되지 않음"으로 남겨뒀던 사항의 확정이다.
- 추가로 업로드 방식에 파일 선택(클릭) 외에 **드래그앤드롭**도 지원해야 한다는 요청이 있었다.

## 범위
- 수정: `output/01_upload_matching.html`(그룹 일괄 입력 패널 이식 + 드래그앤드롭 추가 + 스텝/버튼 정리), `output/03_detail_analysis.html`·`output/04_prediction.html`·`output/analysis_dashboard.html`(상단 nav에서 "수기입력" 항목 제거)
- 이동: `output/02_manual_entry.html` → `history/`(더 이상 별도 화면이 아니므로 폐기, `history/README.md`에 대체 문서 명시)
- 문서 동기화: `prd.md`(§6-①/②, §10-20 해결 처리), `.docs/02_nextjs-fastapi-구현-아키텍처.md`, `.docs/04_기술-스택-정의서.md`, `.docs/05_mvp-구현-실행계획.md`, `.docs/06_mvp-todo-list.md`, `.docs/phase/phase_01_plan.md`, `.docs/07_디자인-수정-이력.md`(신규 이력), `CLAUDE.md`(프로젝트, output 파일 구성 설명), `history/README.md`
- 비범위: 실제 코드/드래그앤드롭 업로드 로직 구현(아직 Next.js 코드 자체가 없음 — 이번 작업은 정적 목업과 기획 문서 수준), 분석 로직·DB 스키마 변경

## 방법
1. `01_upload_matching.html`의 두 `dropzone`에 드래그앤드롭 안내 문구(끌어다 놓기/클릭 선택)와 `dragover`/`drop` 이벤트를 처리하는 최소 vanilla JS를 추가해, 실제 구현에서 그대로 참고할 수 있는 인터랙션 패턴을 보여준다.
2. `02_manual_entry.html`의 "그룹 일괄 입력" 카드(충전량 형명 단위, 전해액온도·수조온도 형명+생산일자 단위)와 관련 요약 카드(`summary-row`)·안내(`alert`)를 `01_upload_matching.html`의 매칭 결과 표 아래로 그대로 이식한다.
3. `01_upload_matching.html`의 `steps` 인디케이터를 "업로드·매칭·수기입력(한 화면, 완료)" → "1단·2단 분석 실행" 2단계로 단순화하고, 하단 액션 버튼을 "수기입력 확인으로 이동"에서 "1단·2단 분석 실행"으로 바꾼다.
4. 나머지 화면들의 nav에서 "수기입력" 항목을 제거해 실제 화면 구성과 일치시킨다.
5. `prd.md` §6을 "업로드+매칭+수기입력이 한 화면(3개 기능 섹션)"으로 갱신하고 §10-20을 해결 처리한다. 나머지 `.docs/*` 매핑 문서에서 `manual-entry/page.tsx`·`/manual-entry` 경로를 제거하고 `upload/page.tsx`에 통합한다.
6. `.docs/07_디자인-수정-이력.md`에 새 이력 항목을 추가하고, `history/README.md`에 `02_manual_entry.html` 이동을 기록한다.

## 완료 기준
- `output/*.html` 5개 파일의 nav가 실제 화면 구성(업로드 화면 하나로 통합)과 일치.
- `grep`으로 `manual-entry`·`02_manual_entry.html`·"수기입력 확인으로 이동" 등 구 경로/문구가 이동·수정 의도와 다르게 남아있지 않은지 확인.
- `prd.md`·`.docs/*`가 새 화면 구조(2단계 스텝, 통합 페이지)를 일관되게 서술.
