# 24. 채점 모듈 및 데모/테스트 버전 분리 구현 계획

## 배경/동기

`.docs/23`(튜터 조언 정리)과 이 대화에서 사용자가 직접 확정한 검증·성공/실패 기준(`.docs/22` §0,
2026-09-24)을 실제로 코드에 반영하기 위한 구현 계획이다. 확정된 기준 요약:

| 항목 | 결정 |
|---|---|
| 성공 판정 축 | SPEC 합격/불합격 일치(예측 판정 == 실측 판정) |
| 참고 오차율 | ±10%(성공/실패를 가르진 않지만 같이 기록) |
| 신뢰 가능 임계값 | SPEC 판정 일치율 90% 이상 |
| 실패 처리 | 자동 재실행·사람 검토 트리거 없이 **로그만 적재**(1차 구현) |
| 버전 분리 | DB 파일만 분리(`app_demo.db`/`app_test.db`), 코드는 하나 |

## 범위

1. DB 프로필 분리(환경변수 스위치) — 데모 버전과 테스트 버전이 서로 다른 SQLite 파일을 쓰게 함
2. 채점 모듈(`backend/analysis/scoring.py`) — 시험 매칭된(실측이 있는) 로트를 대상으로, 저장된
   회귀계수로 재예측한 뒤 SPEC 판정을 실측과 비교
3. 채점 결과·실패 케이스 로그 저장(신규 테이블) + 조회 API
4. **명시적으로 하지 않는 것**: 이번 채점은 회귀 학습에 쓰인 표본을 그대로 다시 예측하는
   **in-sample 검증**이다 — 별도로 떼어둔 holdout(train/val 분리) 검증이 아니다. 정식 train/val
   분리·R²/RMSE 검증은 `docs/prd.md` §3에서 이미 v2 Non-goal로 명시돼 있으므로 그 범위를 침범하지
   않는다. 이번 채점의 목적은 "회귀가 실측과 얼마나 자주 같은 판정을 내리는가"를 1차로 가시화하는 것.

## 방법

### 1) DB 프로필 분리
- `backend/db/repository.py`의 `DB_PATH`를 환경변수 `AX_DB_PROFILE`로 결정하도록 수정 —
  미설정 시 지금과 동일하게 `app.db`(데모 버전, 기본값 유지라 하위호환 깨지지 않음), `test`면
  `app_test.db`(테스트 버전).
- 기존 pytest는 `monkeypatch.setattr(repo, "DB_PATH", ...)`로 직접 덮어쓰고 있어(확인됨,
  `tests/backend/test_prediction_repo.py` 등 3곳) 이 변경의 영향을 받지 않는다.
- `history/21`에서 만든 파이프라인 검증용 더미 데이터(`더미 데이터_process.csv`/`_test.xlsx`,
  batch 36/37)는 `app_test.db`로 옮기고, 기존 `app.db`(데모용)에서는 그 검증용 행을 지운다 —
  `.docs/22` §1의 "더미 데이터 정리 여부 결정" 항목과 연결.
- `uvicorn` 실행 커맨드에 `AX_DB_PROFILE=test` 지정 예시를 CLAUDE.md "자주 쓰는 명령어"에 추가.

### 2) 채점 모듈

**설계 수정(2026-09-24, 리뷰 중 발견)**: 당초 계획은 `sae_cca`/`en_cca`(방전량 Ah) 회귀의 예측값을
그대로 채점하려 했으나, **EN/SAE CCA 합격배지(대시보드에 이미 노출 중)는 방전량이 아니라 전압·지속시간
체크포인트로 판정된다**(`analysis/cca_spec.py`, 사용자가 준 실제 스펙: EN은 10초 전압≥7.5V AND
6.0V까지 지속시간≥90초, SAE는 7.2V까지 지속시간≥30초 — `config/spec_thresholds.py`에 이미 반영돼
있음). 기존 `xy_to_sae_cca`/`xy_to_en_cca` 회귀는 이 체크포인트를 예측하지 않으므로, "예측 합격/불합격"
자체가 없어 채점이 불가능했다. 해결책: 체크포인트 3개(`en_cca_10s_voltage`, `en_cca_6v_hold_sec`,
`sae_cca_7v2_hold_sec`)를 X로 예측하는 회귀를 새로 만들어 "예측 합격/불합격"을 실제로 만들어낸다.
표본은 이번 더미 데이터 40건 전부 체크포인트가 채워져 있어(확인됨) 충분하다.

- `backend/analysis/regression.py`에 신규 공개 함수 3개 추가(기존 `fit_xy_to_sae_cca` 패턴 그대로):
  `fit_xy_to_en_cca_voltage10s`, `fit_xy_to_en_cca_hold6v`, `fit_xy_to_sae_cca_hold7v2` — 전부
  `[*X_COLUMNS, "retention_rate"]` → 해당 체크포인트 필드로 `_fit_linear` 호출.
- `backend/analysis/scoring.py`(순수 함수, DB·웹 프레임워크 비의존): 시험 매칭 로트(실측 Y·Z·CCA
  체크포인트가 있는 로트) 전체를 입력받아 **그때그때 4계열 회귀를 새로 학습**(y, xy_to_z, 체크포인트
  3개)하고, 학습에 쓴 바로 그 로트들에 대해 재예측 → `judge_spec`/`judge_en_cca`/`judge_sae_cca`로
  "예측 판정 vs 실측 판정" 비교. **`AnalysisRun` 등 기존 스키마는 건드리지 않는다**(비영속 학습이라
  CHECK 제약 enum 확장·테이블 재생성이 필요 없음 — 마이그레이션 리스크 없이 진행).
- 대상 target 4종: `y`, `z`, `en_cca_spec`(전압+지속시간 두 서브모델 조합), `sae_cca_spec`(지속시간
  한 서브모델)을 각각 독립적으로 채점.
- 반환값: 전체 건수, 판정 불가(SPEC 미설정 등) 제외 유효 건수, 일치/불일치 건수, 일치율(%), 90%
  임계치 대비 "신뢰 가능" 여부(bool), 오차율(참고용, ±10% — y/z/체크포인트 값 자체의 근접도), 불일치
  로트 목록(=실패 케이스, 로트별 예측값·실측값·오차율 포함).
- `backend/db/repository.py`에 조회 함수 `get_scoring_rows(conn)` 신규 추가 — 시험 매칭 로트 전체를
  TestData ⋈ LotDerived ⋈ Lot ⋈ ConstantsByModel로 한 번에 반환(y/z/체크포인트 3개 값 전부 포함).

### 3) 채점 결과·실패 케이스 로그
- `schema.sql`에 신규 테이블 추가(기존 테이블 변경 없음 — `CREATE TABLE`만 추가라 안전, 재생성
  불필요):
  - `ScoringRun`: run_id(PK) · target · run_at · threshold_pct(=90.0) · n_total · n_scorable ·
    n_matched · n_mismatched · success_rate · reliable(bool)
  - `ScoringResult`: id(PK) · run_id(FK) · lot_id · predicted_value · actual_value · error_pct ·
    predicted_spec_result · actual_spec_result · matched(bool)
- 신규 라우터 `backend/routers/scoring.py`:
  - `POST /api/scoring/run?target=y|z|sae_cca|en_cca` — 채점 실행 + 저장
  - `GET /api/scoring/latest?target=...` — 최근 채점 결과 + 불일치(실패) 로트 목록 조회
- 화면 반영(대시보드에 배지 등)은 이번 1차 구현 범위에서는 제외 — API까지만 만들고, 필요해지면
  별도 요청으로 진행.

## 완료 기준
- `AX_DB_PROFILE=test`로 띄운 백엔드가 `app_test.db`를 쓰고, 미설정 시 기존과 동일하게 `app.db`를
  쓰는 것을 확인.
- `pytest tests/backend`(기존 66건) 그대로 통과 + `scoring.py`/`get_scoring_rows`/`routers/scoring.py`
  단위·API 테스트 신규 추가.
- `POST /api/scoring/run?target=y`(및 z/sae_cca/en_cca)를 실제 curl로 호출해 일치율·불일치 로트
  목록이 응답에 나오는 것을 확인.
- `history/21` 더미 데이터(EN/SAE 각 10합격/10불합격으로 설계된 값)로 채점을 돌렸을 때 "불일치(실패)
  케이스"가 실제로 잡히는지 확인(시스템이 자기 자신을 속이지 않는지 검증하는 최소한의 셀프체크).

## 실행 결과(2026-09-24, 완료)

전부 계획대로 구현·검증 완료(`pytest` 77건 통과, `ruff` 통과). 실제 채점 결과(테스트 프로필,
`history/21` 더미 40건 기준): y=70.0%, z=55.0%, en_cca_spec=70.0%, sae_cca_spec=72.5% — 전부
90% 임계값 미달으로 `reliable: false`. 표본이 적은 단순 선형회귀 in-sample 채점이라 당연한
결과이지만, "지금 이대로는 아직 신뢰 가능 수준이 아니다"를 실제 수치로 확인한 것이 이번 작업의

전부(기존 AGM70_S1 12개월 추이 1,200행 포함) 삭제됨. 전부 더미 데이터라 사용자 확인 하에 복구하지
않기로 함(원상복구 필요 시 `scripts/generate_agm70_trend_dummy.py` 재실행으로 동일 복원 가능).
