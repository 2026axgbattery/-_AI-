## 범위

**백엔드 (`backend/analysis/`, 웹 프레임워크 비의존 순수 함수 원칙 유지)**
1. `significance.py`: `pearson_p(x, y)` — `scipy.stats.pearsonr`로 r/p-value 반환, 유의수준 0.05 고정(`correlation-reliability-review.md`와 동일 기준).
2. `vif.py`: `compute_vif(df, columns)` — 1단 X셋에 대해 `statsmodels` 없이 직접 계산(각 X를 나머지 X로 회귀한 R²에서 `1/(1-R²)`) — 의존성 추가 없이 numpy만으로 구현.
3. `regression.py`:
   - `fit_x_to_y(rows)`: 1단 X셋(`electrolyte_temp`, `tank_temp`, `soaking_time_sec`, `aging_days`, `formation_dv`, `cell_weight_mean`, `cell_weight_std`, `charge_ratio`) → `retention_rate` 다중선형회귀(scikit-learn). `fill_weight`/`water_loss`/`mt_voltage`/`mt_current`는 함수 내부에서 화이트리스트로 원천 차단.
   - `fit_xy_to_z(rows)`: 1단 X셋 + 실측 `retention_rate` → `discharge_amount`. 시험 매칭 로트만 사용.
   - `fit_x_to_z_baseline(rows)`: 1단 X셋만 → `discharge_amount`.
   - `predict_y(coefficients, rows)` / `predict_z(coefficients, rows)`: Day 3에서 쓸 순수 적용 함수(계수 딕셔너리 + X 딕셔너리 → 예측값). Day 2에서 회귀와 함께 미리 만들어 둔다(Day 3 재사용, 근거: `phase_02_plan.md` "다음날 연계").
4. `trend.py`: `aggregate_by_period(rows, period)` — `prod_date` 기준 day/month/year 집계(평균 Y, 표본 수).
5. `db/repository.py`에 회귀 입력 조회 함수 추가: 1단 대상(수기입력 3항목 모두 채워진 로트의 `LotDerived`+`ProcessData`), 2단 대상(그중 `TestData` 매칭 로트), `AnalysisRun` upsert(같은 stage의 `is_latest_for_stage`를 0으로 내리고 새 행 1 삽입), `GET /api/kpi`용 집계 조회, 형명별 group-by 조회, 추이 조회.
6. `routers/dashboard.py`: `POST /api/analysis/x-to-y`, `POST /api/analysis/xy-to-z`, `POST /api/analysis/x-to-z-baseline`, `GET /api/kpi`, `GET /api/analysis/latest?stage=`(최신 run 조회, 프런트 초기 로드용).
7. `routers/detail_analysis.py`: `GET /api/models/summary`, `GET /api/models/{model_name}/trend?period=`.
8. `backend/config/spec_thresholds.py`: 형명별 상세 분석의 "표본 부족" 판단 임계값(`MIN_SAMPLE_SIZE_FOR_MODEL_DETAIL` 등, 하드코딩 금지 — `prd.md` §10-16).
9. `tests/backend/`: `test_significance.py`, `test_vif.py`, `test_regression.py`, `test_trend.py` — 알려진 입력(예: 완전 상관 X→Y)으로 계수·p-value·VIF가 기대값과 맞는지 검증.

**프런트엔드**
10. `frontend/app/dashboard/page.tsx`: `output/analysis_dashboard.html` 이식. KPI 카드, ③-1(X→Y) 상관·회귀계수·VIF 바 차트, ③-2(X+Y→Z + 베이스라인) 계수 비교, stage별 "최근 학습 시점" 분리 표시, 화면 진입 시(또는 버튼으로) 세 회귀를 실행하고 결과를 렌더링. `design.md` 토큰 그대로 사용(신규 CSS 불필요, 기존 `theme.css`/`components.css` 재사용).
11. `frontend/app/detail-analysis/page.tsx`: `output/03_detail_analysis.html` 이식. 용량군 요약 카드 + 35개 형명 테이블(표본 수 n 항상 표시, 임계값 미만은 "표본 부족" 배지), 형명 선택 시 Y 추이(일/월/연 토글, inline SVG로 직접 렌더링 — 외부 차트 라이브러리 없음).
12. `frontend/lib/api-client.ts`: 위 신규 엔드포인트 호출 메서드 추가.
13. `frontend/app/upload/page.tsx`의 "1단·2단 분석 실행" 버튼: 지금까지 `disabled` 고정이었던 것을 실제로 `/dashboard`로 이동하는 링크(또는 분석 실행 트리거)로 전환.
14. `frontend/components/`: KPI 카드·VIF 바 차트 등 재사용 컴포넌트가 필요하면 이번에 분리(목업 마크업 구조를 보고 그때그때 판단).

## 방법

- 화면당 API를 먼저 만들고 `curl`로 응답 형태를 확인한 뒤 프런트를 이식하는 순서(Day 1과 동일 검증 습관).
- 회귀는 scikit-learn `LinearRegression`(이미 `requirements.txt`에 있음, 추가 의존성 없음). VIF는 별도 라이브러리 없이 numpy로 직접 구현(`statsmodels` 미설치 상태 유지, 불필요한 의존성 추가 금지).
- 1단 학습 대상 로트 조건: 수기입력 3항목(`electrolyte_temp`/`charge_amount`/`tank_temp`)이 모두 채워져 있고 `LotDerived.retention_rate`가 NULL이 아닌 로트(raw data 지원으로 `retention_rate`가 NULL일 수 있게 됐으므로 이 필터가 실질적으로 중요, `.docs/14` 참조).
- 2단/베이스라인 학습 대상: 위 조건 + `TestData` 매칭.
- 표본이 회귀에 필요한 최소 개수(변수 수+1) 미만이면 각 API가 400과 함께 사유를 반환(에러가 아니라 "표본 부족" 정상 케이스로 프런트에 안내).

## 완료 기준 (`phase_02_plan.md` 그대로)

- Y 추이 그래프가 실제 DB 값으로 렌더링(하드코딩 좌표 없음).
