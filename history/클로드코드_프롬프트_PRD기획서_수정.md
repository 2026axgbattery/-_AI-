# 확정 구조 (이번 수정의 핵심)

기존 PRD는 X→Y 회귀 1단만 있었다. 이를 **2단 캐스케이드**로 바꾼다.

```
1단:  X (공정인자, process_data)        →  Y (포화도)
2단:  X + Y (포화도)                    →  Z (20시간 용량)
최종: X만 입력하면 Y와 Z를 연달아 예측  (시험을 거치지 않은 로트도 커버)
```

- **Z = 20시간 용량**이다. `test_data.csv`의 `charge_amount_20h` / `discharge_amount` / `capacity_rate` 중 어느 것이 20시간율 용량인지 데이터로 판별하고, 판별 근거를 문서에 남겨라. 확정할 수 없으면 Open Question으로 올려라.
- 기존 PRD가 `capacity_rate`를 포화도(Y)로 잠정 매핑해둔 것은 **재검토 대상**이다. 20시간 용량이 Z로 확정된 이상, `capacity_rate`는 `용량 / 정격용량` 형태의 **Z 계열 지표**일 가능성이 높다. 아래 "Y 정의 분기" 참조.

## 학습·추론 규칙 (반드시 이대로 설계할 것)

이 부분은 사용자가 처음 설명한 것과 다르게 잡아야 하는 지점이니 문서에 명시적으로 써라.

1. **2단 모델의 학습은 "예측된 Y"가 아니라 "실측 Y"로 한다.** 예측값으로 학습하면 1단의 오차가 2단에 그대로 각인되어 편향이 누적된다.
2. **추론(운영) 시에만** 1단의 예측값 Ŷ를 2단에 투입한다. 즉 학습 시 입력과 추론 시 입력이 다르다는 점(train-inference mismatch)을 문서에 리스크로 기재하고, v2에서 오차 전파 검증을 하도록 이관한다.
3. **베이스라인 모델을 반드시 함께 만든다**: `X → Z` 직접 회귀. 캐스케이드가 이 베이스라인보다 나은지 비교해야 "포화도가 성능의 매개변수다"라는 이 과제의 전제가 검증된다. 비교 지표 산출 자체는 v2로 넘겨도 되지만, **모델 구조와 저장 스키마에는 처음부터 자리를 만들어 둘 것.**
4. 시험 매칭 로트(59개)만이 2단 학습 데이터다. 미매칭 41개는 학습에 기여하지 않는 **순수 추론 대상**임을 명확히 구분해 기술하라.

## Y 정의 분기 (미결 사항이므로 두 갈래로 설계)

Y(포화도)의 출처가 무엇이냐에 따라 1단의 성격이 달라진다. **어느 한쪽으로 단정하지 말고, 설정으로 전환 가능한 구조로 PRD에 기술하라.**

- **분기 A — 측정형**: Y가 시험 데이터에 있는 값이면, 1단은 진짜 "예측"이고 학습 데이터는 59개다.
- **분기 B — 계산형**: Y가 `process_data`의 `fill_weight`(주액량)·`water_loss`(감액량)로 산출되는 값이면, 1단은 예측이 아니라 **계산**이며 100개 로트 전부 Y를 갖는다. 이 경우 1단 회귀의 역할은 "예측"이 아니라 **"어떤 공정인자가 포화도를 움직이는가"라는 인자 영향도 규명**으로 바뀐다.

데이터모델에 `saturation_source` (`measured` | `derived`) 필드를 두고, 두 경로 모두 지원하도록 설계하라. 담당자 확인 전까지는 분기 B(계산형)를 기본값으로 두되, 그것이 잠정 결정임을 문서에 명시하라.

# PRD 수정 지시 (섹션별)

기존 섹션 번호 체계를 유지하면서 수정한다.

### §1 문제 정의
- "시험 전 로트는 깜깜이다"라는 고통을, 2단 구조가 어떻게 해소하는지로 연결해 다시 써라. 핵심은 "시험 없이 X만으로 Y와 Z를 모두 얻는다"이다.

### §3 Goals
- 목표를 캐스케이드 기준으로 재작성: "X→Y→Z 2단 관계를 정량화하고, X만으로 Y·Z를 동시 산출한다"
- 기존 정량 목표(월 10시간 → 2시간, 80% 단축)는 유지

### §5 기능 목록 / §6 MVP 상세
- 기존 ①~⑤ 화면 골격은 유지하되, ③ 분석과 ④ 예측을 **1단/2단으로 분리**해 기술하라.
  - ③-1: X→Y 상관·회귀 + 인자 영향도
  - ③-2: X+Y→Z 회귀 (+ X→Z 베이스라인)
  - ④-1: 미매칭 41개 로트 Y 산출/예측
  - ④-2: 그 Ŷ를 2단에 넣어 Z 예측
- **⑤ SPEC 판정을 Y와 Z 양쪽에 적용**하도록 확장하라. 현재는 포화도만 판정하게 되어 있다.

### §6-③ X 인자셋 — 반드시 고칠 논리 결함
현재 PRD는 회귀 X에 `MT(V)`·`MT(A)`를 포함하는데, 이 둘은 `test_data.csv` 소속이다. 미매칭 41개 로트는 test 데이터가 없으므로 **입력 X값 자체가 존재하지 않아 예측이 불가능**하다. 성공지표의 "예측 커버리지 100%"도 현 상태로는 달성 불가다.

- **1단 X는 `process_data.csv` 컬럼만으로 구성하라.** MT(V)/MT(A)는 X에서 빼고, "시험 로트 한정 심층 분석" 용도로만 남겨라.
- MT(V)/MT(A)가 실제로는 공정 설정값이어서 전 로트에 존재한다면 process 쪽으로 이관하면 된다는 점을 Open Question으로 남겨라.
- 물리적으로 포화도와 직결되는데 현재 X에서 빠져 있는 인자를 추가하라: `fill_weight`, `water_loss`, `soaking_time_sec`, `cell1~6_weight`(평균·표준편차), `voltage_2nd − voltage_1st`, `aging_days`. `bath_no`·`circuit_no`는 인자가 아니라 **통제/층(group) 변수**로 구분해 기술하라.

### §6-③ 정규화 (기존 Open Question 4 해결)
통계적 그룹 표준화 대신 **물리적 무차원화**로 대체하라. 모델 크기 효과가 원천 제거되고 해석 가능성도 확보된다.

| 원본 | 파생인자 |
|---|---|
| `fill_weight` | `fill_weight / rated_capacity` (g/Ah) |
| `water_loss` | `water_loss / fill_weight` (감액률 %) |
| `water_loss` | `water_loss / 과충전Ah` (g/Ah) — 이론 상수와 직접 비교 가능 |
| `charge_amount` | `charge_amount / rated_capacity` (충전율 %) |
| `cell1~6_weight` | 평균 / 표준편차 (셀 간 편차를 별도 인자로 분리) |

회귀 실행 시 **VIF 산출·표시**를 대시보드 요구사항에 추가하라.

### §6 신규 기능 — 감액 분해 로직
`water_loss`(전지 중량 감소량으로 측정됨)를 통값으로 회귀에 넣지 말고 분해하라. `charge_amount`만 있으면 구현 가능하므로 **MVP 범위에 포함**한다.

```python
theoretical_water_loss = 0.336 * overcharge_ah
water_loss_residual    = water_loss - theoretical_water_loss
```

잔차 해석 규칙을 표로 기술하라: 크게(+) → 증발·산 미스트·누액 과다 / 0 근방 → 정상 / 크게(−) → 화성 부족·계량 오류·재결합 과다. AGM은 VRLA라 산소 재결합으로 실측이 이론보다 작을 수 있다는 단서를 달아라. 임계값은 초기 데이터 분포로 잡고 담당자가 튜닝 가능하게 설계한다.

### §7 데이터 모델
- **`ConstantsByModel`** 신규: `model_name`(PK), `rated_capacity`, `void_volume_separator`, `void_volume_plate`, `free_volume`, `design_fill_weight`, `fill_sg`, `spec_lower_y`, `spec_lower_z`
- **`LotDerived`** 신규: `retention_rate`, `water_loss_rate`, `water_loss_per_ah`, `theoretical_water_loss`, `water_loss_residual`, `fill_per_rated`, `charge_ratio`, `cell_weight_mean`, `cell_weight_std`, `formation_dv`, `saturation_calc`(nullable), `saturation_basis`(`cell`|`separator`|`proxy_retention`), `saturation_source`(`measured`|`derived`), `derived_at`
- **`AnalysisRun`**: `stage` 필드 추가 (`x_to_y` | `xy_to_z` | `x_to_z_baseline`)
- **`Prediction`**: `target` 필드 추가 (`y` | `z`), 그리고 `input_y_source` 필드 (`measured` | `predicted`) — 어떤 Y를 넣어 나온 예측인지 추적
- **`SpecJudgment`**: Y와 Z 각각 판정할 수 있도록 `target` 필드 추가

`saturation_basis`·`saturation_source`는 화면과 보고서에 항상 병기하라. 잔존율을 포화도로 오독하는 것을 막는 안전장치다.

### §8 엣지 케이스 — 아래 항목 추가
- `water_loss`가 음수이거나 이론 전기분해량보다 작음 → 계량 오류/화성 부족 플래그, 회귀 제외 여부 담당자 선택
- 산출 포화도가 0~100% 범위 밖 → 공극 상수 또는 계량 오류로 차단
- 동일 `bath_no`/`circuit_no` 로트의 계통 편차 → 로트가 독립이 아님(계층 구조). 단순 OLS는 표준오차를 과소평가 → 조/회로별 잔차 분포를 대시보드에 표시
- 다중공선성(`fill_weight` ↔ `rated_capacity` 등) → VIF 임계 초과 시 경고
- **2단 예측 시 1단 오차가 전파됨** → Z 예측값에 "Ŷ 기반"임을 플래그로 표시, 실측 Y 기반 예측과 구분
- 중량 측정 시점·저울 불일치 → 20kg급 전지에서 수십 g을 판별하는 0.1% 수준 신호이므로, 전·후 동일 저울/측정 시점 통일/표면 부착액 제거를 데이터 수집 SOP로 명시

### §9 성공 지표
- **예측 커버리지 재정의**: X 인자셋을 process 한정으로 고친 뒤 "미매칭 41개 로트의 Y·Z 산출률 100%"로 다시 쓴다
- **추가**: 캐스케이드 vs `X→Z` 베이스라인 비교 구조가 구현되어 있을 것 (수치 비교는 v2)
- **추가**: `water_loss_residual` 분포로 이상 로트가 실제로 검출되는지 1건 이상 확인
- R²/RMSE 정식 검증을 MVP 성공지표로 올리지 마라 (v2 유지)

### §10 Open Questions — 아래를 추가하고 기존 3·4번은 해결/재정의 처리
1. `capacity_rate`·`discharge_amount`·`charge_amount_20h` 각각의 정확한 산식과, 이 중 무엇이 Z(20시간 용량)인지
2. 사내에서 "포화도"라고 부르는 값의 실제 정의 — 셀 전체 기준인지 세퍼레이터 기준인지, 만충 기준인지, 측정형인지 계산형인지
3. `MT(V)`·`MT(A)`는 공정 설정값인가 측정 결과값인가
4. `water_loss` 측정 SOP — 측정 시점(주액 직후/흡수 후), 저울 분해능, 동일 저울 사용 여부
5. 과충전 Ah 산출 가능 여부 (`charge_amount`가 총 화성 Ah인지, 이론 용량 대비 비율인지)
6. 화성 후 비중 데이터 확보 가능 여부
7. 모델별 공극부피 상수(세퍼레이터 사양·극판 공극률) 확보 가능 여부
8. Y와 Z 각각의 SPEC 하한값 (모델/정격용량별로 다른지 포함)

### §12 신규 섹션 — 단계별 실행 경로
공극부피 상수와 화성 후 비중이 집체 전에 확보되지 않을 가능성이 높다. 그 경우의 현실적 경로를 명시하라.

- **MVP**: Y = 잔존율/감액률(전 로트 계산 가능)로 진행, `saturation_basis = 'proxy_retention'`으로 표기. 감액 분해 로직 포함. 2단 구조와 베이스라인은 스키마·화면 골격까지 구현
- **v2**: 비중·공극 상수 확보 후 `saturation_calc` 활성화, 해체 중량법 실측(샘플 20~30개)으로 잔존율↔실제 포화도 회귀식 검증, 학습/검증 분리와 R²·RMSE 정식 검증, 오차 전파 검증

# 용어 정의 섹션 신설 (§1 뒤 또는 §7 앞)

아래 3개를 **별개 용어로 구분**해 표로 정의하라. PRD 전체에서 혼용을 금지한다.

| 용어 | 정의 | 산출 가능 범위 |
|---|---|---|
| 포화도(saturation) | 전해액 부피 / 총 공극(void) 부피 × 100 | 공극 상수 확보 시에만 |
| 잔존율/감액률 | `(fill_weight − water_loss) / fill_weight` | 전 로트 즉시 산출 |
| capacity_rate | 시험 측정값 (산식 확인 필요) | 시험 로트만 |

포화도 정의에 반드시 병기할 것: 총 공극 = 세퍼레이터 공극(압착 상태 기준) + 극판 공극(화성 후 기준) + 자유 공간. 기준은 **셀 전체 / 세퍼레이터** 중 명시, **SOC는 만충 기준**, **압착률 명시**.

# 도메인 상수 (PRD 부록에 그대로 기재)

검증된 값이니 그대로 써라.

- 유효 화성 1 Ah당: H₂SO₄ **+3.66 g** 방출(극판→액), 물 **−0.672 g** 소모 → 액 질량 순 **+2.99 g**
- 과충전 1 Ah당: 물 전기분해 **0.336 g** 손실 (전지 중량 감소로 나타남)
- 전지 **전체** 중량 기준이면 극판→액 황산 이동은 내부 이동이라 상쇄되므로, `water_loss`는 외부 유출분만 잡는다
- 액 질량 역산 (화성 후 비중 확보 시):
  `m₁ = [ m₀·(1 − 0.817·c₀) − water_loss ] / (1 − 0.817·c₁)`, `V₁ = m₁ / ρ₁`, `S = V₁ / V_void × 100`
  (`c` = 황산 질량분율, 비중 환산 시 온도보정 필수)
- 해석 주의: 액 부피는 거의 변하지 않는데도 포화도가 떨어지는 경우가 많다. 화성으로 **분모(극판 공극)가 커지기 때문**이다. 원인진단 규칙이 무조건 "주액량 증대"로 향하지 않도록 설계할 것

# 기획서(docx) 수정 지시

`python-docx`로 편집한다. **표 구조·서식·행 개수를 바꾸지 말고 해당 셀의 텍스트만 교체**하라. 원본은 백업본을 남기고 새 파일로 저장한다.

- **표 8 (To-Be, 완성 후 기대 모습)**: 2단 캐스케이드로 다시 써라. "공정인자(X)만 입력하면 포화도(Y)와 20시간 용량(Z)을 연달아 예측하는 웹앱" 취지가 드러나야 한다.
- **표 9 (예상 Workflow)**: ①~⑤ 흐름을 1단/2단이 보이도록 갱신하라. ③을 ③-1(X→Y)·③-2(X+Y→Z)로, ④를 ④-1(Y 산출)·④-2(Z 예측)로 나눠 쓰고, MT(V)/MT(A)를 수기입력 5개 항목에서 어떻게 처리할지 반영하라.
- **표 1 (과제 선정 이유)**: "X-Y-Z 연결관계 정량 분석" 문구가 이미 있으니, 2단 캐스케이드라는 구현 방식이 드러나도록 한 문장 보강.
- **표 7 (기대효과)**: "시험을 거치지 않은 로트도 포화도와 용량을 사전 예측" 취지를 추가.
- **표 5(투입시간), 표 6(정량 효용성)**: 수치는 그대로 유지. 표 5의 오기 정정 각주도 그대로 둔다.
- **표 0 (기본정보)**: 수정하지 마라.
