# 21. 형명 60/70Ah 신규 더미 데이터 생성 및 파이프라인 검증 계획

## 배경/동기
- 사용자가 `AGM 시험현황_raw data.xlsx`(CCA·20시간 용량 원본 raw 포맷)와 `agm70_trend_process_data.csv`(공정 CSV 포맷)를 예시로 들며, 같은 형식의 새 더미 데이터를 만들어 업로드→매칭→회귀→SPEC/CCA 배지 파이프라인이 지금 실제로 잘 도는지 확인해 달라고 요청함.
- 목적은 "그럴듯한 신규 수치"가 아니라 **파이프라인 동작 검증**이므로, 로트별로 합격/불합격이 둘 다 나오게 해서 배지·회귀가 정상 분기하는지 보는 것이 핵심.

## 범위
- 공정 데이터: `AGM60_S1`, `AGM70_S1` 두 형명만, 총 약 1,000행(형명별 500행).
- 시험 데이터: 형명별 20건씩(초기상태+20HR용량 전부 채움), 그중 SAE/EN CCA 체크포인트도 20건 전부 채워 회귀 최소 표본(12건, `analysis/regression.py`)을 넉넉히 만족시키고, EN/SAE 각각 합격·불합격이 섞이도록 함.
- 산출 파일: 저장소 루트에 `더미 데이터_process.csv`(`REQUIRED_PROCESS_COLUMNS` 형식), `더미 데이터_test.xlsx`(`backend/etl/test_raw.py`가 읽는 세로 시험항목 트리 구조, 시트 2개).

## 방법
1. 기존 `process_data.csv`의 AGM60_*/AGM70_* 실측 행에서 컬럼별 평균/표준편차/최소/최대를 계산해 분포 파라미터로 재사용(`scripts/generate_agm70_trend_dummy.py`의 `SYNTH_PARAMS` 방식을 두 형명으로 일반화).
2. `lot_id`는 실측 규칙(`060C26`/`070C26` + 월 문자 + 9자리 일련번호 + 바이어 접미)을 그대로 따름 — `ChargeProgramSpec`에 이미 있는 바이어 코드 `S`를 사용해 `charge_program_deviation_pct`가 NULL이 되지 않게 함.
3. 형명별로 생성된 lot_id 중 20개를 뽑아 시험 raw 워크북의 샘플 컬럼으로 사용. EN 판정(10초 전압≥7.5V AND 6.0V 지속시간≥90초)과 SAE 판정(7.2V 지속시간≥30초)이 각각 절반은 합격, 절반은 불합격이 되도록 값 배분(4가지 조합 × 5건: 둘다합격/둘다불합격/SAE만합격/EN만합격).
4. 생성 후 실행 중인 백엔드(`127.0.0.1:8000`)에 `POST /api/upload/process`, `POST /api/upload/test`로 실제 업로드해 매칭·회귀·CCA 배지가 정상 동작하는지 curl로 확인.

## 완료 기준
- 두 파일이 저장소 루트에 생성되고 각각 pandas/openpyxl로 열어 행 수·컬럼이 의도대로인지 확인됨.
- 업로드 API 응답에서 `skipped_unknown_lot`이 비어 있고(=매칭 성공), `/api/analysis/y-vs-cca`·`/api/detail-analysis/models/AGM60_S1/lots`·`.../AGM70_S1/lots` 응답에 EN/SAE CCA pass/fail이 둘 다 나타남.
- `xy-to-sae-cca`/`xy-to-en-cca` 회귀가 `InsufficientSampleError` 없이 정상 수행됨(표본 20건 확보).
