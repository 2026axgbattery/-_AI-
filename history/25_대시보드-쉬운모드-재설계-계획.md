# 대시보드 "쉬운 모드" 재설계 계획

## 2026-09-24 추가 — 전 화면 확산 결정
`/dashboard` 파일럿이 끝난 뒤 사용자가 "이 디자인으로 책정하고 모든 HTML에 적용해달라"고 확정했다. 나머지 3개 화면(업로드/상세분석/예측)과 그 레퍼런스 목업(`output/01_upload_matching.html`, `output/03_detail_analysis.html`, `output/04_prediction.html`)에도 같은 패턴을 적용하되, 화면 성격이 서로 달라 **기계적으로 4종 세트(steps+onboard+hero+insight-row)를 전부 복붙하지 않고 화면별 실제 격차만큼만 적용**한다(조사 결과 기반):
- **업로드**: 이미 `.steps`(3단계 인디케이터)와 카드형 요약(`.match-summary`/`.summary-row`)이 있음 — 가벼운 보강만. 요약 카드에 `.status-chip` 색배지만 추가.
- **예측**: 이미 `verdict-banner`+`verdict-row`+`<details className="evidence">` 선례가 있음(카드형, 다크그레이 히어로는 아님) — `.steps` 추가, `verdict-banner`를 `hero-verdict` 톤으로 격상, 기존 evidence 섹션을 `evidence-toggle`로 통일.
- **상세분석**: 갭이 가장 큼(`.steps`/`hero-verdict`/`evidence-toggle` 전무, 형명별 상세 테이블이 표 나열식) — 3종 모두 신규 추가.
- 각 화면 모두 레퍼런스 목업(`output/*.html`)과 실제 Next.js 페이지 양쪽을 함께 갱신하고, 실제 페이지는 매번 `npm run build`/`npm run lint`로 확인한다.

## 배경/동기
`/dashboard`는 이미 Layer 1(결론 요약)/Layer 2(근거, `<details>` 접이식) 구조를 갖추고 있지만, 한 화면에 접이식 근거 섹션이 5개(1단 상관·회귀, 2단 캐스케이드 vs 베이스라인, Y↔CCA 참고, SPEC 판정&원인진단, 검증·채점) + 표 8개 이상이 몰려 있고, 그중 첫 섹션은 기본으로 펼쳐져 있어 진입 즉시 VIF·p-value·R²·회귀계수 같은 통계 용어가 노출된다. 비전공자(품질 담당자 등)가 "지금 상태가 좋은지 나쁜지"를 한눈에 파악하기에는 여전히 정보 밀도가 높다는 사용자 피드백에 따라, `/dashboard`를 파일럿으로 삼아 구조를 다시 짠다.

사용자가 확정한 방향(질문 3개에 대한 답):
1. **범위**: `/dashboard` 먼저 파일럿(전체 5개 화면 동시 작업 아님).
2. **전문용어 처리**: "쉬운 모드"를 기본값으로 하고, 화면 상단 토글로 "전문가 모드"(현재의 통계 수치·용어 전부)로 전환 가능하게.
3. **레이아웃 변경 폭**: 화면 구조를 대폭 재설계해도 됨(카드 구성, 정보 순서, 섹션 전체 노출 여부까지 바꿀 수 있음).

추가 확인(2차 피드백): 이 화면은 "나 혼자 보는 화면"이 아니라 **팀 전체가, 특히 처음 입사한 신입 직원도 설명 없이 바로 쓸 수 있어야** 한다. 사용자가 요구한 결론: "모든 사람이 이 데이터로부터 확실한 답을 얻는다." 이를 위해 다음을 추가로 반영한다.
1. **업로드 → 결과 확인 → 상세 조회, 3단계 흐름을 화면에서 명시적으로 드러낸다.** 지금도 `TopBar`에 업로드/대시보드(결과 확인)/상세분석·예측(상세 조회) 4개 메뉴가 있지만, 사용자가 "지금 내가 어느 단계에 있는지" 인지하지 못한다 — 페이지 상단에 작은 3단계 흐름 표시(진행 인디케이터)를 추가해 방향 감각을 준다.
2. **결과를 훨씬 더 강하게 강조한다.** Y/Z 판정을 카드 4개로 나열하는 데 그치지 않고, 그 위에 "이번 데이터는 전체적으로 괜찮은가?"에 대한 **단 하나의 초대형 결론 배너**(큰 아이콘 + 큰 글자 + 색상)를 최상단에 둔다 — 신입 직원이 스크롤 없이 3초 안에 "정상/확인 필요"를 알 수 있어야 한다.
3. **"자세한 상황은 조회해서 확인"을 모드 토글에만 의존하지 않는다.** 전문가 모드 토글(통계 근거 접기/펼치기)은 유지하되, 그와 별개로 결론 배너·요약 카드 각각에 "형명별로 자세히 보기 →"(`/detail-analysis`), "원인 진단 보기 →"(`/prediction`) 같은 **명확한 이동 CTA**를 붙여, 이미 존재하는 상세 화면으로 자연스럽게 넘어가게 한다. 페이지 하나에 모든 걸 우겨넣지 않고, "한눈에 보기(이 화면)"와 "자세히 조회(다른 화면)"의 역할을 분리한다.
4. **용어의 위축감을 줄인다.** "전문가 모드"라는 이름이 신입 직원에게 진입장벽처럼 느껴질 수 있어, 버튼 라벨을 "통계 근거 자세히 보기"처럼 무엇을 보여주는지 설명하는 문구로 바꾸고, 토글이 아니라 그냥 "더 보기" 성격으로 인지되게 한다.
5. **가독성**: 결론 배너·요약 카드의 폰트 크기를 한 단계 키우고(타이틀 1.75rem대), 카드 아이콘을 통일된 크기로, 여백을 넉넉히 둬 스캔하기 쉽게 한다. 색상은 `docs/design.md` 시맨틱 토큰만 사용(신규 색상 금지 원칙 유지).

## 범위
- 대상 파일: `frontend/app/dashboard/page.tsx`, `frontend/app/components.css`(필요한 클래스만 추가/확장)
- 비범위: 백엔드 API·분석 로직 변경 없음(순수 프레젠테이션 계층), 다른 4개 화면(업로드·상세분석·로트드릴다운·예측) 구조 변경 없음(이번 파일럿에서 검증 후 다음 라운드에서 확산), `docs/design.md` 토큰 범위를 벗어나는 신규 색상 도입 없음.
- 구조 확정 전 확인용으로 `output/06_dashboard_easy_mode.html`에 정적 목업(더미 데이터)을 먼저 만들어 사용자 확인을 받은 뒤, 승인된 구조를 `frontend/app/dashboard/page.tsx`에 이식한다(기존 `output/analysis_dashboard.html` → Next.js 이식 방식과 동일).

## 방법

### 1. 모드 토글
- `const [easyMode, setEasyMode] = useState(true)` — 기본값 쉬운 모드. `localStorage`에 저장해 새로고침 후에도 유지(`try/catch`로 감싸 접근 실패 시 기본값 유지).
- 페이지 헤더(`page-head`) 우측에 기존 `.period-tabs`/`.period-tab` 패턴을 그대로 재사용한 2버튼 토글("쉬운 모드" / "전문가 모드") 배치 — 새 CSS 컴포넌트를 만들지 않고 기존 클래스 재사용.

### 2. 진행 흐름 표시 (신규)
페이지 최상단, `page-head` 위에 3단계 흐름 인디케이터(`.steps`/`.step`, 기존 클래스 재사용 — `upload/page.tsx`에서 이미 쓰는 패턴)를 배치: "① 업로드" → "② 결과 확인(지금 여기)" → "③ 상세 조회". 현재 단계(②)만 강조 색상, 나머지는 회색 — 신입 직원이 "지금 보고 있는 화면이 전체 흐름 중 어디인지" 바로 인지하게 한다. ①은 `/upload`, ③은 대표로 `/detail-analysis`로 링크.

### 3. 초대형 결론 배너 (신규, Layer 0)
기존 `verdict-banner`보다 한 단계 위 레벨로, 페이지 최상단(흐름 인디케이터 바로 아래)에 **단 하나의 종합 결론**을 초대형으로 보여준다: 큰 상태 아이콘(✅/⚠️/❔) + "이번 데이터, 전체적으로 괜찮은가요?"에 대한 한 문장 답 + 큰 배지("정상"/"확인 필요"/"판정 불가"). 로직: `specCompliance`의 y_fail+z_fail 합이 0이면 정상, 1건이라도 있으면 "확인 필요"(오렌지), SPEC 미설정이면 "판정 불가"(그레이). 문구는 전문용어 없이 순수 결론만("현재 20시간 용량 기준에 못 미치는 로트가 2건 있어요 — 자세히 보기에서 어떤 로트인지 확인하세요" 등).

### 4. Layer 1 — "한눈에 보기" 요약 카드 4개 + 이동 CTA
기존 `verdict-banner`(결론 문장)는 유지하되 쉬운 모드에서는 상관계수(r=…)·p-value 같은 수치 각주를 문장에서 제거하고, 그 아래 이미 존재하는 `.verdict-card.status-{ok|fail|unknown}` 컴포넌트를 활용해 4장짜리 카드 그리드(`.insight-row`, `components.css`에 4열 그리드 신규 추가, `.verdict-row`와 동일한 반응형 규칙)를 새로 배치한다. 새 API 호출 없이 이미 받아온 `kpi`/`specCompliance`/`scoring`/`keyFinding`으로만 계산:
1. **포화도(Y) 판정**: `specCompliance.y_fail` 유무로 ok/fail/unknown. 카드 하단에 "형명별로 보기 →"(`/detail-analysis`) CTA.
2. **20시간 용량(Z) 판정**: `specCompliance.z_fail` 유무로 ok/fail/unknown. 카드 하단에 동일 CTA.
3. **가장 큰 영향 인자**: `keyFinding` 1위 인자를 문장으로("○○이(가) 가장 큰 영향" + 방향), 통계 기호 없이. 카드 하단에 "원인 진단 보기 →"(`/prediction`) CTA.
4. **검증 신뢰도**: `scoring`의 4개 target 중 `reliable===true`가 하나라도 있으면 ok, 전부 `false`면 fail(미달), 전부 미실행이면 unknown("아직 채점 안 함").

### 5. Layer 2 — "통계 근거 자세히 보기"(구 "전문가 모드")
이름을 "전문가 모드"에서 **"통계 근거 자세히 보기"**로 바꿔 위축감을 줄인다(토글 자체는 유지: 기본은 접힌 상태, 누르면 기존 5개 `<details className="evidence">` 섹션이 그대로 나타남 — 로직·문구 변경 없음). 접힌 상태에서는 `.alert` 카드 한 장으로 "상관계수·회귀계수·VIF 같은 통계 근거는 여기서 펼쳐볼 수 있습니다" 안내만 노출. 재계산 트리거(1단·2단 분석 실행 버튼)는 두 상태 공통으로 페이지 헤더에 유지.

### 6. 스타일 · 가독성
- `components.css`에 `.insight-row`(4열 그리드, 모바일 1열), `.hero-verdict`(초대형 결론 배너) 클래스 추가. 나머지는 기존 `.verdict-card`, `.status-pill`, `.alert`, `.steps/.step` 재사용 — `docs/design.md` 색상 토큰(오렌지=경고, 그린-700=양호, 그레이=미상) 그대로 사용, 신규 색상 없음.
- 결론 배너·카드 타이틀 폰트를 기존보다 한 단계 키우고(예: 카드 값 1.75rem → hero는 2.25rem 이상), 카드 내부 여백을 넉넉히 둬 스캔하기 쉽게 한다.

## 완료 기준
- 신입 직원이 설명 없이 화면에 들어와도 3초 안에 "지금 데이터가 괜찮은지"를 초대형 결론 배너로 알 수 있음.
- 흐름 인디케이터로 "업로드 → 결과 확인 → 상세 조회" 중 지금 어디인지 바로 인지 가능.
- 요약 카드 각각에서 관련 상세 화면(형명별 상세/예측)으로 한 번의 클릭으로 이동 가능(CTA 링크).
- "통계 근거 자세히 보기"를 펼치면 기존 화면(5개 근거 섹션)이 그대로, 손실 없이 보임.
- 펼침 상태는 새로고침 후에도 유지(localStorage).
- 구조 확정 전 `output/06_dashboard_easy_mode.html` 정적 목업으로 먼저 사용자 확인.
- (Next.js 이식 단계에서) `npm run build`/`npm run lint` 통과, `run` 스킬로 실제 브라우저에 띄워 콘솔 에러 없이 렌더링되는지 확인.
