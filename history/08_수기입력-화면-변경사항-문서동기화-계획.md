# 수기입력 화면(`output/02_manual_entry.html`) 변경사항 문서 동기화 계획

## 배경/동기
`output/02_manual_entry.html`을 두 차례 수정했다.
1. MT(V)/MT(A) 표시 자체를 삭제(기존에는 "편집 불가능한 참고 배지"로 노출하고 있었음).
2. "로트별 수기입력 항목" 표(로트별 자동값 프리뷰 + 예외 로트 개별 입력 UI)를 통째로 삭제하고, 그룹 일괄 입력 패널만 남김.

`prd.md`와 `.docs/` 하위 문서들은 이 두 변경 이전 상태(=MT(V)/MT(A) 참고 배지 노출, 그룹 일괄 + 개별 편집 병행)를 전제로 작성돼 있어 실제 화면과 문서가 어긋난다. 특히 (2)는 "그룹값과 다른 예외 로트는 개별 수정도 허용한다"는 기존 요구사항 자체를 화면에서 제거한 것이므로, 삭제 사실과 함께 예외 처리가 현재 미해결 상태임을 문서에 명시해야 한다.

## 범위
- 수정: `prd.md`(§6-②, §10 오픈 이슈 추가), `.docs/02_nextjs-fastapi-구현-아키텍처.md`, `.docs/04_기술-스택-정의서.md`, `.docs/06_mvp-todo-list.md`, `.docs/phase/phase_01_plan.md`, `.docs/07_디자인-수정-이력.md`(신규 이력 항목 추가)
- 비범위: 실제 코드/DB 스키마(아직 미착수), `output/` 내 다른 화면 파일, MT(V)/MT(A) 데이터 모델 자체(변경 없음 — 여전히 `test_data.csv` 매칭으로 채워지는 참고 컬럼)

## 방법
- "화면에는 편집 불가능한 참고 배지로만 노출한다" 류 서술 → "이 화면에는 노출하지 않는다"로 수정.
- "개별 수기 편집"/"개별 편집" 관련 서술 → 화면에서는 그룹 일괄 입력만 제공하고 개별 예외 편집 UI는 제공하지 않는다는 사실로 수정하고, 그룹으로도 해소되지 않는 예외 로트 처리 방법을 `prd.md` §10에 새 오픈 이슈로 추가.
- `GET/PUT /api/lots/{lot_id}/manual-fields`(개별 편집 API)는 화면과 연결되지 않는 상태임을 각 문서에 명시(백엔드 API 자체를 없앨지는 오픈 이슈로 이월, 이번 작업에서 결정하지 않음).
- `.docs/07_디자인-수정-이력.md`에 이번 두 변경을 새 이력 항목으로 추가.

## 완료 기준
- `MT\(V\)|MT\(A\)|개별.*편집|개별.*입력` 키워드로 재검색해 새 화면 상태와 불일치하는 서술이 남아있지 않음을 확인.
- 예외 로트(그룹값과 다른 값이 필요한 로트) 처리 방법이 미해결 오픈 이슈로 `prd.md` §10에 기록됨.
