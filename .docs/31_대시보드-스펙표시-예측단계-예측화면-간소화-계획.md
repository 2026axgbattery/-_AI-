# 31. 대시보드 히어로 글자정렬·SPEC값 표시, 4단계 흐름(예측 포함), 예측 화면 간소화 계획

## 배경/동기

`.docs/30`(히어로 평균값 우선 재배치) 직후 실제 화면 스크린샷 2장을 받음: (1) 히어로의 "CCA 합격률"
지표 카드가 라벨 중간에서 줄바꿈되는 등 글자 배열이 깨져 있었고, SPEC 하한이 얼마인지는 여전히
안 보임. (2) 화면 흐름 인디케이터가 "① 업로드 → ② 결과 확인 → ③ 상세 조회"까지만 있고 예측 화면이
빠져 있음. 추가로 사용자는 이번 작업을 "전체적으로 마무리하는 작업"으로 규정하며 (a) `/prediction`을
처음 보는 사람도 바로 쓸 수 있는 구조로 간소화하고 (b) "조건이 바뀌면 Y·Z가 어떻게 바뀌는지", "시험
전 로트의 Z가 얼마나 나올지"를 바로 확인할 수 있게 하며 (c) PRD·부속 문서를 다시 읽고 방향을 재정렬할
것을 요청함.

## 범위

1. `/dashboard` 히어로 지표 카드 CSS 버그 수정(`max-width:62ch`가 3열 그리드 전체에 걸려있던 것이
   원인) + 라벨 줄바꿈 방지(`word-break:keep-all`).
2. SPEC 하한값 자체를 히어로에 노출 — `GET /api/spec-compliance`에 `spec_lower_y_min/max`,
   `spec_lower_z_min/max` 추가(형명마다 다를 수 있어 범위로 표시, 값이 같으면 단일 값).
3. 4개 화면(`/dashboard`·`/detail-analysis`·`/prediction`, `/upload`는 자체 내부 진행률이 있어 제외)
   에 중복돼 있던 "① 업로드 → ② 결과 확인 → ③ 상세 조회" 마크업을 `components/StepFlow.tsx`로
   통합하고 ④ 예측을 추가 — 부수적으로 `/prediction` 사본이 활성 단계 라벨을 "③ 상세 조회"로 잘못
   표시하던 버그도 같이 고침(복사-붙여넣기 잔재로 추정).
4. `/prediction`(조건 시뮬레이션 탭) 간소화:
   - 모든 입력칸이 `placeholder="예: 31.2"`로 동일했던 버그 수정 — 필드별 실제 스케일에 맞는
     예시값(`X_COLUMN_EXAMPLES`, `process_data.csv` 실측 범위 참고)으로 교체.
   - "예시값으로 채우기" 버튼 추가 — 처음 여는 사람이 빈 칸 9개를 보고 막막해하지 않도록.
   - 재실행 시 직전 예측 대비 Y·Z·SAE/EN CCA 변화량("이전 예측 대비 +N")을 결과 카드에 바로
     표시 — "조건을 바꾸면 결과가 어떻게 달라지는지"를 매번 수동 비교하지 않아도 바로 보이게 함.
   - 탭 라벨·안내문구를 사용자가 쓴 두 가지 실제 질문("조건을 바꾸면?", "시험 전 로트는?") 그대로
     반영.
5. 범위 밖(의도적으로 보류): 배치 탭 자동 실행(클릭 없이 즉시 계산), 입력값 자동 채우기를 실제
   형명 평균치로 서버에서 가져오는 기능(신규 엔드포인트 필요, 이번엔 대표 예시값으로 대체),
   `/upload`에 동일한 4단계 표시 추가(자체 내부 3단계와 중복되어 혼란 줄 수 있어 보류).

## 방법

- PRD(`docs/prd.md`) §6 ④(예측)·⑤(SPEC 판정) 재확인 — Y/Z SPEC 하한은 형명별(`ConstantsByModel`)로
  다를 수 있다는 전제(§10-11 미확정)를 재확인하고, 히어로에는 값이 아니라 "범위"로 정직하게 표시.
- 기존 컨벤션 재사용: CCA 판정은 `analysis/cca_spec.py` 고정 임계값, 원인진단은 `diagnosis.py`
  그대로 — 새 분석 로직 추가 없음.
- 프런트 공용 컴포넌트 추출(`StepFlow`)로 3개 화면의 중복 마크업을 제거해 이번 같은 라벨 불일치가
  재발하지 않게 함.

## 완료 기준

- 히어로 카드 3개가 좁은 화면에서도 라벨이 중간에서 끊기지 않고, SPEC 하한(또는 범위)이 보인다.
- `/dashboard`·`/detail-analysis`·`/prediction`에서 흐름 인디케이터가 ①~④ 전부 보이고, 각 화면의
  "지금 여기" 라벨이 실제 화면과 일치한다.
- `/prediction` 조건 시뮬레이션 탭에서 예시값 채우기 → 실행 → 값 하나 변경 → 재실행 시 변화량이
  바로 보인다.
- `pytest tests/backend`·`ruff check backend`·`npm run build`/`npm run lint` 통과, 데모 백엔드
  재시작 후 `/api/spec-compliance`·`/api/kpi`·`/api/predict/manual`·`/api/predict/batch-unmatched`
  curl로 실제 응답 확인.
