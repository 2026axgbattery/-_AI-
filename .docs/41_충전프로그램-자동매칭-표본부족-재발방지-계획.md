# 41. 충전 프로그램 자동 매칭 — "최소 표본 수 미달" 재발 방지 계획

## 배경 / 근본 원인

- 증상: `/dashboard`에서 1·2단 분석 실행 시 "회귀에 필요한 최소 표본 수 미달: 유효 표본 0건".
- 직접 원인: 1단 X셋에 `charge_program_deviation_pct`(충전 프로그램 기준표 대비 이탈도)가 포함돼 있고, `ChargeProgramSpec`에 (정격용량, 바이어)가 없으면 이 값이 NULL → `_fit_linear`가 NULL 행을 **조용히 전부 제외**해 0건이 됨.
- **재발한 이유(구조적)**: 기준표는 "수동 업로드 1회"에 의존하는 데이터인데, (1) 원본·더미 기준표 xlsx는 `.gitignore`로 저장소에 없고, (2) Render 무료 티어는 디스크가 휘발성이라 슬립/재배포마다 SQLite(기준표 포함)가 초기화됨, (3) 새 컴퓨터 클론·`app.db` 재생성도 동일. 그때마다 "수동으로 올리기"로만 땜질해 왔기 때문에 DB가 비는 순간 똑같은 문제가 반복됨. 또 실패 메시지가 원인(기준표 없음/미매칭 조합)을 알려주지 않아 버그처럼 보임.

## 범위

1. 기준표 **자동 시드**: 서버 기동 시 `ChargeProgramSpec`이 비어 있으면 저장소에 포함된 기준표(`backend/seed/charge_program_default.xlsx`, 더미)를 자동 적재하고 전체 로트 이탈도 재계산. 로컬에 실제 원본("★ 260428 …")이 있으면 그것을 우선.
2. **분석 실행 직전 자가치유**: 1·2단·CCA 분석 실행 시에도 기준표가 비어 있으면 시드 후 진행.
3. **정직한 진단 메시지**: 표본 부족 시 원인(기준표 비어 있음 / N개 로트가 기준표에 없는 (정격용량, 바이어) 조합 — 조합 목록)을 메시지에 포함. 업로드 응답에도 미매칭 건수 포함.
4. 회귀 테스트 추가.

## 완료 기준

- 빈 DB로 기동 → 더미 공정 업로드 → 수동 기준표 업로드 없이 1단 회귀가 동작.
- 기준표에 없는 조합이 있으면 메시지에 조합이 명시됨.
- pytest·ruff 통과, `.docs/07`/CLAUDE.md 함정 항목 갱신.
