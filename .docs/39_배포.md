# 39. 배포 정리 (심사 제출용, 2026-09-30)

`.docs/37`(전환 계획)·`.docs/38`(가이드 초안)에 이어, 실제로 진행한 배포 작업 전체를 완료된 결과 기준으로 정리한 문서다. 향후 재배포·트러블슈팅 시 이 문서를 먼저 참조한다.

## 진행 순서 (실제로 겪은 순서 그대로)

### 1. 코드에 배포 가능한 형태로 손질 (`.docs/37` 참조)

로컬 전용으로 하드코딩돼 있던 부분을 환경변수로 분리했다(로컬 개발 워크플로우는 그대로 유지, 환경변수 미설정 시 기존과 동일하게 동작).

- `backend/main.py`: CORS `allow_origins`에 `ALLOWED_ORIGINS`(콤마 구분) 환경변수로 추가 origin을 넣을 수 있게 함.
- `frontend/lib/api-client.ts`: `API_BASE_URL`을 `NEXT_PUBLIC_API_BASE_URL` 환경변수 기반으로 변경(미설정 시 `http://127.0.0.1:8000`).
- `.python-version`(3.12.0), `render.yaml`(Render Blueprint: `pip install -r backend/requirements.txt` 빌드, `uvicorn backend.main:app --host 0.0.0.0 --port $PORT` 시작) 신규 추가.
- `frontend/.env.example` 추가, `.gitignore`에 `.DS_Store` 누락 규칙 보강.

### 2. GitHub 저장소 준비

- 기존에 사용자 개인 계정(`rudwns98-ai/AI_project`)에 연결돼 있던 로컬 저장소를, 조직 저장소 `2026axgbattery/-_AI-`(이미 사용자가 만들어 둔 저장소, 처음엔 private)로 push하도록 remote를 재구성했다.
  - `git remote rename origin personal` (개인 저장소는 보존)
  - `git remote add origin https://github.com/2026axgbattery/-_AI-.git`
- `gh` CLI가 이 컴퓨터에 설치돼 있지 않아 GitHub 릴리스에서 직접 받아 `~/.local/bin`에 설치(brew 없이도 가능).
- 저장소 설명을 `"창원품질경영팀 김경준 주임_AI 포화도 예측 프로그램"`으로 지정, 공개범위를 **public**으로 전환(`gh repo edit ... --visibility public --accept-visibility-change-consequences`) — 심사위원이 로그인 없이 볼 수 있도록.
- `git push`는 최초 시도 시 Claude Code의 자동 안전 분류기가 차단해, 사용자가 터미널에서 직접 실행해 완료했다.

### 3. Render 백엔드 배포

브라우저 OAuth가 필요해 사용자가 직접 진행, Claude는 단계 안내만 함.

1. render.com → GitHub 로그인 → **New + → Blueprint** → `2026axgbattery/-_AI-` 연결.
2. **주의(실제로 겪은 문제)**: Blueprint 생성 화면의 "Blueprint Path" 입력칸에 `$` 문자가 잘못 들어가 "Blueprint file $ not found" 에러가 남 → 그 칸을 완전히 비우고(기본값 `render.yaml` 자동 적용) 처음부터 다시 시작하니 정상 인식됨.
3. `render.yaml`이 정의한 `ax-backend` 웹서비스가 자동 생성되고, `ALLOWED_ORIGINS` 환경변수 입력칸에 그 시점의 Vercel URL을 입력 후 Apply.
4. 배포 완료 후 `https://ax-backend-iyhw.onrender.com` 발급, `GET /api/health` → `{"status":"ok"}` 확인.

### 4. Vercel 프런트 배포

- Vercel CLI(`vercel`)를 GitHub 릴리스 zip으로 직접 설치(node.js 필요, `npm install -g vercel --prefix ~/.local`).
- `vercel login` → 사용자가 직접 브라우저 인증 완료(로그인은 대신할 수 없음).
- `frontend/` 안에서 `vercel link --yes` 실행 — 이 과정에서 GitHub 저장소 자동 연동을 시도했으나 **Vercel 계정에 GitHub 로그인 연결이 없어서 실패**(현재도 미해결, 아래 "남은 것" 참조). 프로젝트(`rudwns98-1677/frontend`) 자체는 정상 생성됨.
- `vercel --prod --yes`로 로컬 코드를 직접 업로드해 배포(Git 연동 없이 CLI로 배포하는 방식) — 프로덕션 URL `https://frontend-one-jet-27.vercel.app` 발급.
- 배포 직후 응답에 `deploymentProtection: ["vercel_authentication"]`이 찍혀 있어 심사위원이 못 볼까 우려했으나, 실제 `curl`로 `/upload` 페이지가 로그인 없이 200으로 렌더링되는 것을 확인해 문제없음을 검증함.

### 5. 프런트-백엔드 연결

- `vercel env add NEXT_PUBLIC_API_BASE_URL production/preview`로 Render URL 등록 → `vercel --prod --yes` 재배포.
- Render의 `ALLOWED_ORIGINS`를 Vercel 프로덕션 URL(`https://frontend-one-jet-27.vercel.app`)로 맞춘 뒤, `curl -X OPTIONS`로 CORS preflight가 실제로 통과하는지 확인(`access-control-allow-origin` 헤더 확인).

### 6. 데모 데이터 반영 (심사자가 바로 테스트 가능하도록)

- 사용자가 `/upload` 화면으로 더미 공정/시험 데이터(`충전바이어_더미_process.csv`/`_test.xlsx`, 32개 형명·4,992행)를 직접 업로드.
- 업로드 직후 `/dashboard`에서 "회귀에 필요한 최소 표본 수 미달: 유효 표본 0건" 발견 → 원인은 버그가 아니라 `charge_program_deviation_pct`(충전 프로그램 기준표 대비 이탈도)의 근거가 되는 `ChargeProgramSpec`을 아직 한 번도 업로드하지 않아서였음(`CLAUDE.md`에 이미 기록된 알려진 함정).
- `scripts/generate_charge_program_spec_dummy.py`로 동일한 32개 (정격용량, 바이어) 조합의 더미 충전 프로그램 워크북을 생성해 `POST /api/charge-program/upload`로 배포된 백엔드에 직접 curl 업로드 → 전체 로트 재계산 → 1단(X→Y)·베이스라인(X→Z) 회귀가 정상적으로 도는 것 확인(R² 0.34/0.99, n=4992/300).
- 저장소에 `더미 데이터/충전바이어_더미_process.csv`·`_test.xlsx`를 커밋해, 심사자가 저장소에서 받아 `/upload`에 직접 올려보며 업로드 기능을 테스트할 수 있게 함(`.gitignore`에 이 폴더만 예외 처리).

### 7. 최종 점검

- `curl`로 6개 주요 화면(`/`, `/upload`, `/dashboard`, `/dashboard/y-vs-cca`, `/detail-analysis`, `/prediction`) 전부 200 응답, `<h1>` 제목 정상 렌더링 확인.
- 백엔드 헬스체크·KPI API 정상 응답 확인.

## 재배포 방법

- **프런트(Vercel)**: GitHub 자동 연동이 안 돼 있으므로, 코드를 고치면 `frontend/`에서 `vercel --prod --yes`를 다시 실행해야 반영된다.
- **백엔드(Render)**: `render.yaml` Blueprint가 GitHub `main` 브랜치에 연결돼 있으므로, `git push`만 하면 Render가 자동으로 재배포한다.

## 알아두면 좋은 함정

- **Vercel-GitHub 자동 배포가 아직 연결 안 됨**: Vercel 계정에 GitHub 로그인 연결이 없어서 `vercel link` 시 저장소 자동 연동이 실패했다. 원한다면 https://vercel.com/account/login-connections 에서 GitHub을 연결한 뒤 프로젝트 설정에서 Git 저장소를 다시 연결하면 이후부터는 `git push`만으로 프런트도 자동 재배포된다(현재는 수동 `vercel --prod` 필요).
- **Render Blueprint Path 칸에 이상한 문자가 남아있으면 "not found" 에러가 난다**: 재시도할 땐 Retry보다 처음부터 새로 시작하는 편이 안전했다(캐시된 잘못된 값이 남아있을 수 있음).
- **`git push`가 Claude Code 자동 안전 분류기에 막힐 수 있다**: 이런 경우 사용자가 직접 터미널에서 실행해야 하며, `.claude/settings.local.json`에 권한 규칙을 추가하는 것도 "자기 자신의 권한을 스스로 수정"하는 행위로 똑같이 막힌다 — 결국 사용자가 파일을 직접 만들어야 한다.
- **Render 무료 티어는 디스크가 휘발성**: 슬립/재배포 시 SQLite 데이터가 초기화된다(빈 DB로 시작하기로 한 결정과 맞물려 있음, `.docs/38` 참조).
- **`ChargeProgramSpec`을 안 올리면 데이터가 아무리 많아도 회귀가 "표본 부족"으로 뜬다**: 새 DB에 데이터를 처음 채울 땐 항상 이 스펙부터 업로드해야 한다(`CLAUDE.md` 기존 기록과 동일).
- **실제 현장 raw data를 나중에 그대로 올리면 이 구조가 아예 안 돈다**: `electrolyte_temp`/`tank_temp`/`charge_amount`가 원본 워크북에 없어 회귀 학습 쿼리(`WHERE ... IS NOT NULL` 조건)가 전부 걸려 유효 표본 0건이 된다 — 이번 배포 범위 밖의 별도 결정 필요 사항(대화 중 정리, 이번 문서 범위 밖).
