# 27. 부적합(SPEC 미달) 로트 원인진단 화면 — 작업 계획서

## 배경/동기

- 사용자 요청(2026-09-25): "부적합이 된 로트를 따로 조회해서 어떤 X인자가 문제인지 확인해주고, 해당 부분에 대해서 상세 분석이 가능하도록 정리해줘."
- `/dashboard`의 SPEC 준수 KPI는 실측값 기준 부적합 **건수**(예: Y 43건 미달)만 보여주고, **어떤 로트인지·왜 미달인지**는 어디서도 확인할 수 없었다(조사 결과 확인 — `get_spec_compliance_summary`는 COUNT만 반환, lot_id 목록을 반환하는 API/repository 함수 자체가 없었음).
- 원인진단 로직(`analysis/diagnosis.py`의 `judge_spec`/`rank_causes`/`compute_factor_means`)은 이미 구현돼 있고 `/prediction`(미매칭 로트 예측)에서 쓰이고 있지만, **예측값에만 연결돼 있고 실측값이 있는 이미 시험 완료된 로트에는 적용된 적이 없다.** 함수 자체는 예측/실측을 가리지 않는 순수 함수라 재사용 가능.

## 범위

- 새 화면/섹션 1개: 실측 Y·Z가 SPEC 하한 미달인 로트 목록 + 로트별 원인진단(상위 기여 X인자 3개, `rank_causes` 그대로 재사용).
- 대상은 **시험 매칭 완료(has_test=true) + SPEC 설정된 형명**의 로트만 — 미시험 로트는 대상 아님(그건 `/prediction`의 몫).
- CCA(EN/SAE)는 이번 범위에서 제외 — CCA는 `spec_lower_y/z` 같은 형명별 커스텀 SPEC이 아니라 고정 규격(EN 50342/SAE J537) 판정이라 판정 방식이 다르고, 이미 `cca_spec.py` 배지로 보여주고 있음(`/detail-analysis` 로트별 표).

## 방법

**백엔드**
1. `backend/db/repository.py`에 `get_failing_lots(conn)` 신규 — `Lot`+`LotDerived`(retention_rate)+최신 `TestData`(capacity_rate)+`ConstantsByModel`(spec_lower_y/z) 조인, `retention_rate < spec_lower_y OR capacity_rate < spec_lower_z` 로트만 반환. 1단 X셋 컬럼(`electrolyte_temp`/`tank_temp`/`soaking_time_sec`/`aging_days`/`formation_dv`/`cell_weight_mean`/`cell_weight_std`/`charge_ratio`/`charge_program_deviation_pct`) 전부 같이 반환해야 `rank_causes` 입력으로 쓸 수 있음.
2. `backend/routers/dashboard.py`(또는 `detail_analysis.py`, 위치는 구현 중 자연스러운 쪽으로 결정)에 `GET /api/spec-compliance/failing-lots` 신규 — `get_failing_lots` 호출 후 로트별로:
   - Y 미달이면 `judge_spec(retention_rate, spec_lower_y)` + `rank_causes(X_COLUMNS_STAGE1, xy_to_y 최신 AnalysisRun 계수, 해당 로트 X값, 1단 학습표본 평균)`.
   - Z 미달이면 동일하게 2단(xy_to_z) 계수로.
   - 계수·평균은 최신 `AnalysisRun`(x_to_y/xy_to_z) 재사용, 새 학습 없음. 학습된 run이 없으면(회귀 미실행) causes는 빈 배열 + 안내 문구.
3. `Prediction`/`SpecJudgment`/`CauseDiagnosis` 테이블에 저장하지 않음(그 테이블들은 `prediction_id` FK로 예측 전용 흐름에 묶여 있어 스키마 변경 없이는 재사용 불가 — 이번엔 그때그때 계산만 하는 조회 전용 API로 범위를 좁힘, "실측 진단 결과 영속화"는 필요해지면 별도 스키마 확장으로 v2 처리).

**프런트엔드**
4. `/detail-analysis`에 접이식 섹션(`.evidence-toggle` 또는 신규 `<details>`) "SPEC 미달 로트 원인진단"을 추가 — `GET /api/spec-compliance/failing-lots` 호출, 로트별 카드(형명·lot_id·Y/Z 실측값·SPEC 하한·이탈폭) + 기존 `CausesList`/`X_COLUMN_LABELS`/`specBadge` 패턴(`/prediction`에서 이미 쓰는 것과 동일 컴포넌트·클래스, `finding-list`/`finding-item`) 그대로 재사용해 상위 기여 X인자 3개를 보여줌.
5. `frontend/lib/api-client.ts`에 응답 타입(`FailingLotDiagnosis` 등) + `getFailingLots()` 추가.

**곁들여 처리**: 사용자가 같이 요청한 "게이지 4개(Y·Z·CCA 2개) 배치를 2x2로 깔끔하게" — `.gauge-row`가 `repeat(auto-fit, minmax(340px,1fr))`라 화면 폭에 따라 3+1로 어색하게 wrap되는 문제. `frontend/app/detail-analysis/page.tsx`의 `.gauge-row`를 `repeat(2, 1fr)` 고정 2열로 변경(작은 화면에서는 기존 `@media (max-width:960px)` 규칙으로 1열).

## 완료 기준

- `GET /api/spec-compliance/failing-lots`가 실제 데모 DB에서 Y/Z 미달 로트 목록 + 로트별 상위 3개 원인 X인자를 반환.
- `/detail-analysis`에서 해당 목록을 확인하고, 로트를 펼치면 `/prediction`과 동일한 시각 언어(원인진단 리스트)로 원인이 보임.
- 게이지 4개가 2x2로 깔끔하게 배치됨(Y·Z 위, EN·SAE CCA 아래).
- `pytest tests/backend`·`ruff check backend`·`npm run build`/`npm run lint` 통과.
