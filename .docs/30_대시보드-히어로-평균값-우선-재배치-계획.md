# 30. 대시보드 히어로(Layer 0) — "평균 결과" 우선 재배치 계획

## 배경/동기

`/dashboard`의 초대형 결론 배너(hero-verdict)가 지금은 "SPEC 미달 로트가 있다"는 경고만 헤드라인으로
보여준다. 사용자 피드백: 제일 먼저 보여줄 내용은 특정 로트를 확인하라는 경고가 아니라 **X→Y→Z 인자의
평균적인 결과**(포화도 Y, 20시간 용량 Z, CCA)와 "지금 데이터는 전반적으로 이상이 없다/있다"는 결론이어야
한다. "확인이 필요한 로트가 있다"는 안내는 메인 헤드라인이 아니라 그 아래 보조 카드로 내려가야 한다.

## 범위

- 백엔드: `GET /api/kpi` 응답에 20시간 용량(Z, capacity_rate 기준)·SAE/EN CCA 합격률 집계를 추가한다
  (현재 `avg_retention_rate`만 있고 Z·CCA 평균이 전혀 없음 — 이 값 없이는 히어로에 "평균 Z·CCA"를
  보여줄 수 없다).
- 프런트: `hero-verdict` 배너를 "경고 헤드라인"에서 "평균 Y/Z/CCA 값 + 전반적 정상여부 결론"으로
  교체한다. 기존에 이미 하단 `insight-row`에 있던 포화도(Y)/20시간 용량(Z) 카드(각각 "29건 미달"/
  "기준 충족" 형태로 미달 로트 안내를 담당)는 그대로 두어 "해당 로트 확인" 안내 역할을 계속 맡는다 —
  이미 히어로보다 아래에 있으므로 별도 이동 작업은 불필요하고, 히어로가 더 이상 같은 경고를 headline으로
  중복하지 않도록만 고친다.
- 범위 밖: SPEC 판정 로직 자체 변경, 새 원인진단 기능, `/prediction`·`/detail-analysis` 변경.

## 방법

1. `backend/db/repository.py`의 `get_kpi_summary`에 `avg_capacity_rate`(로트별 최신 시험 매칭 기준,
   `get_spec_compliance_summary`가 이미 쓰는 것과 동일한 `capacity_rate` 컬럼) 쿼리 추가.
2. `backend/routers/dashboard.py`의 `get_kpi()`에서 `repo.get_model_cca_checkpoints(conn)`을 형명
   구분 없이 전체 집계해 `en_cca_evaluated/en_cca_pass/sae_cca_evaluated/sae_cca_pass`를 KPI 응답에
   병합(`routers/detail_analysis.py`의 `models_summary()`가 이미 쓰는 것과 동일한
   `judge_en_cca`/`judge_sae_cca` 패턴 재사용, 새 판정 로직 없음).
3. `frontend/lib/api-client.ts`의 `KpiSummary`에 위 4~5개 필드 타입 추가.
4. `frontend/app/dashboard/page.tsx`:
   - `buildHeroVerdict`를 `kpi`+`specCompliance`를 받아 Y/Z/CCA 평균값 3개 미니 지표(각자 톤: 실측
     기준 미달 있으면 warn, SPEC/기준 자체가 없으면 unknown, 그 외 ok)와 전체 톤/타이틀을 반환하도록
     재작성.
   - 히어로 본문에 지표 3개를 보여주는 작은 행(`hero-metrics`, 신규 클래스— 기존 spacing/색상
     토큰만 사용)을 추가. warn일 때만 "N건은 아래에서 확인하세요 ↓" 같은 보조 한 줄을 작게 덧붙인다
     (헤드라인이 아니라 부가 정보로).
   - 기존 `insight-row`의 Y/Z 카드·문구는 유지(이미 "해당 로트 확인" 역할).

## 완료 기준

- `/api/kpi` 응답에 Z·CCA 평균이 포함되고, 값이 없을 때(SPEC 미설정/CCA 미평가)도 500 없이 null/0으로
  정직하게 내려온다.
- 히어로 배너 첫인상이 "경고"가 아니라 "평균 Y/Z/CCA + 전반적 정상 여부"로 바뀌고, 미달 로트 안내는
  헤드라인이 아니라 그 아래(기존 insight-row Y/Z 카드)에서만 보인다.
- `pytest tests/backend`·`ruff check backend`·`npm run build`/`npm run lint` 통과.
