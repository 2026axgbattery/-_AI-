# 37. 심사용 외부 배포 전환 계획

## 배경/동기

심사 제출을 위해 이 앱을 외부(사내망 밖)에서 접속 가능하게 배포해야 한다. 현재 구조는
`docs/prd.md`·`CLAUDE.md`의 "전 구간 로컬 처리만 허용(사외반출 금지 데이터, 외부 API 호출 금지)"
원칙에 따라 프런트가 `127.0.0.1:8000` FastAPI만 바라보도록 하드코딩돼 있어(`frontend/lib/api-client.ts`),
그대로는 Vercel에 프런트를 올려도 백엔드에 연결할 수 없다.

사용자 확인 사항(2026-09-30):
- 백엔드 호스팅: **Render 무료 웹서비스**
- 노출 데이터: **빈 DB로 시작**(심사자가 업로드부터 직접 테스트) — 로컬 더미 데이터는 배포본에 포함하지 않음

이번 전환은 "심사 제출을 위한 임시 배포"이며, 실제 현장 데이터(사외반출 금지 대상)는 전혀 다루지
않는다는 전제 하에 진행한다.

## 범위

1. `backend/main.py`의 CORS `allow_origins`를 환경변수로 구성 가능하게 변경(Vercel 도메인 허용).
2. `frontend/lib/api-client.ts`의 `API_BASE_URL`을 `NEXT_PUBLIC_API_BASE_URL` 환경변수 기반으로 변경
   (미설정 시 로컬 개발 기본값 `http://127.0.0.1:8000` 유지 — 로컬 워크플로우 회귀 없음).
3. `frontend/.env.example`(커밋 가능, 값 없음) 추가 + `frontend/.gitignore`에 예외 규칙 추가.
4. Render 배포에 필요한 부속 파일: `.python-version`(3.10+ 고정), `render.yaml`(선택, 문서화 우선).
5. 배포 안내 문서(`.docs/38_render-vercel-배포-가이드.md` 또는 이 문서 하단)에 실제 계정 연동이
   필요한 수동 단계(Render/Vercel 대시보드 조작)를 정리 — 이 부분은 Claude가 대신 실행할 수 없음.
6. Render 무료 티어 디스크 휘발성(재시작 시 SQLite 초기화) 한계를 문서에 명시.

## 방법

- 코드 변경은 최소한으로: 하드코딩된 값을 환경변수로 빼는 수준. 회귀/분석 로직·DB 스키마 변경 없음.
- 로컬 `AX_DB_PROFILE`/기존 `./backend/.venv` 실행 흐름은 그대로 유지(환경변수 미설정 시 기존 동작 100% 동일).
- 변경 후 `pytest tests/backend`·`ruff check backend`·`npm run build`/`npm run lint`로 회귀 확인.

## 완료 기준

- 로컬에서 환경변수 없이 실행 시 기존과 동일하게 동작(회귀 없음).
- `NEXT_PUBLIC_API_BASE_URL`·`ALLOWED_ORIGINS` 환경변수로 임의의 외부 주소를 가리킬 수 있음.
- Render/Vercel 배포 절차가 문서로 정리돼 사용자가 그대로 따라 할 수 있음.
- 빌드/린트/테스트 통과.
