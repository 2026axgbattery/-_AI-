# 35. 업로드 미리보기 + 홀드아웃(train/val) 검증 + 그래프·결과 임팩트 강화 계획

## 배경/동기

사용자가 코드 리뷰 결과 리스트(우선순위별) 중 **"업로드 미리보기"**, **"실제 train/val 분리"** 두
항목을 골라 구현을 요청했고, 추가로 **"그래프나 결과가 나올 때 임팩트를 더해서 눈에 확 들어오게"**
개선도 함께 요청했다. 작업 후 관련 문서(`docs/prd.md`, `.docs/06`, `.docs/07`, `.docs/10`,
`CLAUDE.md`)를 전부 갱신한다.

**주의**: `docs/prd.md` §3은 "train/val 분리"를 **"Non-goals(→v2, 10월)"**로 명시하고 있었다
(`backend/analysis/scoring.py` 모듈 docstring도 동일하게 설명). 오늘 날짜(2026-09-30)가 이미
"10월" 문턱이고 사용자가 명시적으로 이 작업을 요청했으므로, 이번 작업을 **v2 착수 항목**으로
문서에 반영한다(비목표를 몰래 뒤집는 게 아니라, PRD에 "v2 착수"로 명확히 기록).

## 범위

### A. 업로드 미리보기(dry-run)
- `backend/db/repository.py`의 `ingest_process_rows`/`ingest_test_rows`에 `dry_run: bool = False`
  파라미터 추가 — 끝에서 `conn.commit()` 대신 `conn.rollback()`을 호출해 실제로는 아무것도
  저장하지 않으면서 기존 파싱·검증 로직(중복 lot_id, model_name 파싱 실패, 미매칭 lot_id 등)을
  100% 그대로 재사용한다(별도 미리보기 전용 파서를 새로 만들지 않음 — 로직 두 벌 관리 방지).
- `backend/routers/upload.py`의 `POST /api/upload/process`·`POST /api/upload/test`에
  `dry_run: bool = Query(False)` 쿼리 파라미터 추가, 응답에 `"preview": bool` 포함.
- 프런트(`app/upload/page.tsx`): 파일 선택 시 먼저 `dry_run=true`로 호출해 "총 N행 · 신규 로트
  M건 · 중복 K건 · 인식 실패 J건" 요약 카드를 보여주고, 사용자가 "반영하기"를 눌러야 실제
  커밋(`dry_run=false`)이 일어나도록 변경. 파일은 브라우저 `File` 객체를 그대로 들고 있다가
  확인 시 재전송(서버 쪽 세션 상태 불필요).

### B. 홀드아웃(train/val) 검증
- `backend/analysis/scoring.py`: 매칭 로트를 고정 시드로 셔플해 80/20 분할, **학습은 train
  세트로만, 채점은 val 세트로만** 수행하도록 4개 채점 함수(`score_y`/`score_z`/
  `score_en_cca_spec`/`score_sae_cca_spec`) 전면 수정. 분할이 무의미할 만큼 표본이 적으면
  (`val` 세트가 최소 표본 미만) in-sample로 안전하게 폴백하고 `validation_mode`로 그 사실을
  정직하게 표시(지어내지 않음 원칙 유지).
- `backend/db/schema.sql`의 `ScoringRun`에 `validation_mode`/`train_n`/`val_n` 컬럼 추가(이
  컴퓨터는 방금 새로 만든 빈 DB라 스키마 재생성으로 충분 — 기존 `app.db`가 있는 다른 컴퓨터는
  `ALTER TABLE`이 필요함을 CLAUDE.md "알아두면 좋은 함정"에 기록).
- `frontend`: 검증 신뢰도 카드/표에 "홀드아웃 검증(train N건/val M건)" vs "표본 부족으로
  in-sample" 배지를 구분 표시.

### C. 그래프·결과 임팩트 강화
`dataviz` 스킬 로드 완료(색상 재선정 없음, 이미 검증된 팔레트 그대로 재사용 — `.docs/33` 계승).
- 기존에 `isAnimationActive={false}`로 꺼져 있던 Recharts 차트 4종(막대/누적막대/추이선) 진입
  애니메이션을 켠다 — `docs/design.md` 모션 토큰(ease-out, 250~300ms대)에 맞춰 지속시간·이징을
  통일하고, `prefers-reduced-motion`을 존중하는 공용 훅으로 게이팅.
- `components/BatteryGauge.tsx`에 비공개로 있던 카운트업 로직(`useFillAnimation`)을
  `lib/useCountUp.ts`로 추출해 재사용 가능하게 만들고, 대시보드 히어로의 Y/Z/CCA 평균 3개
  숫자·예측 화면 verdict-card의 예측값 숫자에 적용(사용자가 결과를 받는 "제일 먼저 보는 숫자"만
  선별 적용 — `.docs/33`에서 이미 "모든 KPI를 게이지화하면 과함/클러터"라고 결론 낸 바 있어
  숫자 전체에 무분별하게 적용하지 않는다).
- 이미 CSS에 정의만 돼 있고 실제로 쓰인 곳이 없던 `.hero-num-chip`(핵심 수치 인라인 강조 칩,
  팝인 애니메이션 포함)을 히어로 하단 미달 건수 문구에 실제로 연결.

- `npm run build`/`npm run lint` 통과.
- 문서 갱신: `docs/prd.md`(§3 non-goal → v2 착수로 갱신, §10 관련 항목), `.docs/06`,
  `.docs/07`(디자인 변경 이력), `.docs/10`(재개 프롬프트), `CLAUDE.md`(이번 작업 이력 항목 추가).
- 백엔드 재기동 후 실제 API 응답으로 미리보기(dry_run)·홀드아웃 채점 동작 curl 확인.
